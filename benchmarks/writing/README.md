# AnySpark 写作能力实测（第 4 章续写 · 颗粒度矩阵）

> 发起：主人（2026-08-05）| 执行：pi 智能体审核着跑（非固定脚本）| 评审：主人手工阅读
>
> 目的：真实反映 AnySpark 的**写作水平**——在"不同颗粒度剧情提示"下能写成什么样。
> 原则：不埋坑、不预设胜负；每篇我实时驱动（anyspark_api），记录交互行为；产出作品 + 交互日志双产物。

## 测试设计

- **素材**：哈利波特与魔法石（人文社译本）第 1-3 章原文 → 续写**第 4 章「钥匙保管员」**（原著 7095 字）
- **主变量**：剧情脉络颗粒度 4 级（无 / 粗 / 中 / 细），其余变量固定（默认能动性档位、字数要求 ~7000 字）
- **每篇提示词** = 前 3 章原文 + 对应颗粒度脉络 + 统一任务要求（标题保持「第4章 钥匙保管员」，约 7000 字，用 write_chapter 落盘）
- **隔离实例**：`--db data/dev/bench_writing.db`（不污染主库）
- **观察点**：① 系统收到长指令后直接开写还是反问/确认？② 字数是否达标？③ 脉络遵循度（事件覆盖）？④ 设定是否漂移？⑤ Agent 循环行为（工具调用/迭代/压缩）

## 脉络四版

| 级别 | 文件 | 内容 |
|---|---|---|
| 无（对照） | — | 仅前 3 章原文，无脉络提示 |

| 中 | `hp/pitch_mid.md` | 段落级要点（6 条） |

## 判定

- 客观：字数误差 / 设定违规（LLM 裁判）/ 脉络事件覆盖率
- 主观：主人手工阅读 4 篇 + 交互日志，给建议
