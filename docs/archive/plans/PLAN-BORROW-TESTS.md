# PLAN-BORROW-TESTS — 借鉴测试清单（2026-08~11 文献）

> **纪律：先测后改，效果说话。** 本清单是测试计划不是改造计划——每项借鉴先以
> **内容层**实现（workflow 模板 / skill / prompt / 外部脚本调既有 API），不动核心
> 代码；只有实测过决策闸门才立项机制化（机制化另走 DESIGN 偏离确认纪律）。
> 负面结果同样入台账：测了没用=排除一条路线，也是产出。
>
> 来源：2026-11-19 文献调研（S265）。背景：学界在搁置期独立收敛到 AnySpark
> 核心架构（显式叙事状态/伏笔承诺/图规划/章末更新），本清单测的是**增量细节**
> 而非路线推翻。

## 0. 通用实验协议

- **环境隔离**：S262 演示协议——停后端 → `data/` 改名移走 → 空 `data/` 起后端 →
  灌 fixture → 跑臂 → 销毁演示数据 → 移回原数据。各测试互不污染。
- **模型**：writer = 当前激活 `deepseek-v4.1-flash`（thinking off，Token Plan）；
  **judge ≠ writer**（用 `deepseek-v4-pro` 或 glm-5.3），盲评 A/B 匿名 + 顺序对调
  消位置偏好。
- **素材**：写作类用《雾城夜雨》fixture 前 3 章 + 续写至 12~20 章（每臂同大纲同
  种子指令）；RP 类用 2 张角色卡 + 40~60 轮脚本（含 8~10 个对抗探针轮：逼问
  人设定义属性/诱导矛盾承诺）。
- **错误分类法**（judge 逐项锚点举证 + 图谱时序校验交叉，争议人工裁）：
  E1 角色状态（位置/知识/持有物/身心）· E2 时间线 · E3 伏笔/承诺未兑现或矛盾 ·
  E4 设定正典冲突 · E5 文风/人设漂移。
  **CED = 错误数 / 万字**（ConWriter/NstAgent 同口径，便于对外比较）。
- **成本**：每臂记 usage tokens + wall time；效果必须带成本比报告（便宜模型的
  效果增益若被 token 膨胀吃掉=负收益）。
- **通用决策闸门**（满足其一才立项机制化，否则丢弃/搁置）：
  ① CED −30%+ 且成本 ≤1.2×；② CED 持平(±10%) 且成本 −40%+；
  ③ 填补对照组做不到的能力缺口且盲评胜率 ≥70%。
- **样本量**：写作臂 ≥12 章/臂（CED 分母够）；RP 臂 ≥60 轮/臂；盲评 ≥20 对。
  单轮差异不下结论（S250b 教训：假模型/单样本 e2e 只证拓扑不证语义）。

## 2. 测试卡

### T2b logprob 不确定性门控（ConWriter 子测试）——先跑
- **现状对照**：检测网全量跑 / 不跑，二选一；无"哪里该重点查"的信号。
- **可行性**：✅ 2026-11-19 实测 Token Plan `logprobs=true, top_logprobs=3` 返回
  正常（首 token logprob −0.52，含候选分布）。适配器未暴露该参数→测试期外部
  脚本直调 API 取 logprobs，不改适配器。
- **最小实验**：同一段续写（≥6 章）取逐 token logprob → 句级风险分（低 logprob
  句/熵高峰）→ 与 judge 发现锚点做相关：风险分 top-20% 句子是否覆盖 ≥60% 真错误？
- **指标**：召回率/精确率曲线；门控后检查成本比（只查高风险句 vs 全章）。
- **闸门**：top-20% 句覆盖 ≥60% 错误 → 门控立项候选；否则丢弃（logprob 在创作
  文本可能只反映措辞新颖度而非事实风险——这正是高不确定性所在）。
- **成本**：~8 次 flash 调用 + 6 次 pro judge。

### T8 base 模型候选池（Tandem/PMM）——可行性已判死
- **探针结论**：Token Plan 31 模型 / DeepSeek 官方 / 智谱可用端点**全为 instruct
  系**，无 base/pretrained 暴露 → 候选池无源。**搁置**，除非引入 base 端点。
- 保留洞察备用：instruct 助手腔=角色刻板化来源；若未来 RP  fidelity 遇瓶颈，
  先查"腔"再查机制（可用 T6 的记忆 conditioning 部分对冲）。

### T1 类型化角色状态快照 + 章末 Δ 协议（NstAgent）
- **现状对照**：图谱实体（name/type/description/weight）+ 事件 + 每章后台抽取；
  注入=图谱渲染文本。角色"当前状态"散落在 description 自由文本里。
- **借鉴**：角色快照六字段（位置/目标/关系/知识/持有物/身心状态）类型化；章末
  agent 提交结构化 Δ（只改变化字段），写作调用注入快照而非全图渲染。
- **最小实现（内容层）**：skill「角色状态快照协议」+ workflow 模板章末节点
  （agent 产 Δ → 经 setting_register/graph_register 落既有载体）；写作臂用
  write_chapter 的 references 点名快照文本。零代码改动。
- **实验**：4 臂共享续写 run 的一部分——control / T1 / T2 / T1+T2，各 12 章。
- **指标**：E1+E2 CED 分臂；快照维护 token 成本；Δ 漏报率（judge 发现的 state
  变化未进 Δ 的比例）。
- **闸门**：通用①或②；额外观察 T1+T2 是否超加性（状态干净→验证更准）。

### T2 验证通过才提交记忆 + 句级补丁自动触发（ConWriter）
- **现状对照**：后台抽取**立即提交**图谱/伏笔；检测网发现→人工决定改不改；
  定点编辑 patch 能力已有但无自动触发器。
- **借鉴**：① 章末抽取结果先过一致性检查（对照快照/正典/时序），通过才落库，
  违规则句级补丁修复后复检再提交；② 补丁只动违规句不重生成整章。
- **最小实现**：workflow 模板「写→检→gate→提交/补丁→复检」——gate/loop/patch
  原语全已有（S59 工作流 + S44 定点编辑），纯模板组装。
- **指标**：后段章节（7~12 章）CED vs control（错误传播阻断效果）；补丁返工率；
  单章 wall time 增量。
- **闸门**：通用①；若 CED 降但 wall time >2× → 记"效果真但太慢"，候选异步化
  （后台验证不阻塞写作）再测。

### T3 分层角色状态树（PHASE-Tree）
- **现状对照**：角色卡=描述性 markdown 单块；entity_states 平铺字段；长程演化
  靠整卡重写（易炸不变特质）。
- **借鉴**：身份根（不可变：名/核心动机/底色）与可变层（persona/session/moment）
  分离；更新=可寻址字段级 patch，跨 episode 演化只动可变层。
- **最小实现**：角色卡内容重构为分层 markdown + skill「分层更新协议」（agent
  只输出变更层字段）；play/role_play 会话注入分层卡。
- **实验**：RP 臂共享——control 平铺卡 / T3 分层卡 / T4 承诺账本 / T3+T4，
  60 轮含演化事件（角色受伤/得知秘密/立场转变）+ 对抗探针。
- **指标**：不变特质违反数（E5 子类）vs 演化正确率（该变的变没变）；60 轮漂移
  曲线（每 10 轮切片 judge）。
- **闸门**：通用③优先（"演化后状态说话"是对照组结构性做不到的能力）。

### T4 承诺账本 + 高风险轮选择性检查（TaDI）
- **现状对照**：伏笔账本管**叙事**承诺；角色**对话声明**无账本；检测全量或无。
- **借鉴**：原子声明账本（角色说过的承诺/事实声明逐条落账）；不对称约束（人设=
  正蕴含、先前声明=负不矛盾）；只在高风险轮（探针/人设定义属性被触及）跑检查。
- **最小实现**：外部脚本账本（play 会话消息流解析声明→sqlite 临时表）+ 风险轮
  判定 skill；检查走既有 check API。
- **指标**：E3+E5 违反数 vs 全查臂 vs 不查臂；检查调用成本比。
- **闸门**：通用②为主（选择性≈全查效果、成本大降）；若选择性漏掉非探针轮漂移
  → 记负面结论（风险不可局部预测=TaDI 前提在中文 RP 不成立）。

### T5 图拓扑层计划修复（PLOTTER）
- **现状对照**：剧情计划=文本条目；影响分析=文本级报告；修订靠 agent 读文本改
  文本。
- **借鉴**：计划修订在事件图+角色图上做 Evaluate-Plan-Revise：critique 找断因果
  路径/孤立节点 → 原子图操作（增删改边）修复 → 再落文本计划。
- **最小实现**：workflow 模板（graph_query 取子图 → agent critique → graph_register
  修边 → plan 更新），原语全已有。
- **实验**：取含 3 处故意因果缺口的计划 fixture；control 文本修订 / T5 图修订；
  各续写 6 章看缺口是否在下文显形。
- **指标**：因果缺口闭合率；下文 E2/E3 CED；修订 token 成本。
- **闸门**：通用①；图操作若频繁误伤合法边（精确率 <80%）→ 丢弃。

### T6 自传体记忆 conditioning（MemoryForge）
- **现状对照**：角色卡=形容词+设定描述（descriptive conditioning）。
- **借鉴**：为角色合成多分辨率自传体记忆（生涯摘要 + 3~5 个高保真 episodic
  场景），RP 时按情境检索注入取代/补充描述卡。
- **最小实现**：一次性合成脚本（flash 产记忆库→存角色卡附件/资料库条目）；
  play 注入检索片段（reference_lookup 已有）。
- **实验**：2 角色 × 30 轮盲评：描述卡 vs 记忆 conditioning；评"像人/刻板/多样"
  三维度 pairwise + 探针轮一致性不降为前提。
- **指标**：盲评胜率；多样性（回复 n-gram 自重复率）；E5 违反不升。
- **闸门**：通用③（胜率 ≥70%）；合成成本一次性，记入 amortized。

### T7 外部标尺校准（NstAgent bench，非借鉴）
- **用途**：benchmark 自 S211 搁置后 AnySpark 无绝对坐标。拉 NstAgent 开源
  bench（github zhennan1/NstAgent）的 10K~100K 一致性评测协议，把 AnySpark
  当前管线作为一个 system 跑分，与论文报数对照。
- **前置**：clone 仓库读评测协议（judge prompt/CED 口径）→ 对齐本清单分类法。
- **成本**：高（100K 词臂）；先跑 10K/20K 档探路。**按需启动**，不排默认队列。

## 3. 执行顺序与共享 run

1. **T2b 预测力探针**（最便宜、不确定性最高）→ 决定门控路线生死。
2. **写作主 run**：4 臂 ×12 章（control/T1/T2/T1+T2）一次灌 fixture 共享前 3 章。
3. **RP 主 run**：4 臂 ×60 轮（control/T3/T4/T3+T4）共享角色卡 fixture。
4. T5 计划修复 → T6 记忆 conditioning（主观评，放后面避免占用早期注意力）。
5. T7 按需；T8 已搁置。
