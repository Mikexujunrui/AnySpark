## 〇、总评

**哲学主体在实现里活着，但有 3 处"宣称与实现脱节"的实质稀释 + 若干完整度缺口。**
不是"哲学只在文档里"——核心链路（C 架构干净写作、渐进式披露、探索-判别、workflow 组合、
建议非门禁）全部真实可验证；但存在**过期文案教 AI 走错路**（图谱注入宣称）和
**半接通闭环**（信号只剩 modified 活着）这类"哲学被悄悄稀释"的问题，比纯缺实现更隐蔽。

## 一、写作领域图灵完备性四检验

### 1.1 表达完备 ✅（真实）

- 意图通道从种子（explore/intent）→ 方向（DirectionCard）→ 写作（write_chapter intent 模式）
  → 编辑（patch_chapter 定点）→ 收尾（wrapup）全谱覆盖；DEFAULT_SYSTEM 明文支持
  "直接写 / 探索 / 查证 / 编排"多种表达形态。
- 未发现"想做的事系统表达不了"的死角：多线叙事（line 参数）、批量（workflow 集合遍历）、
  推演（play）、评审（panel_review）均有表达入口。

### 1.2 执行完备 ⚠️（真实但有两个断链——第一部分已证）

- **reference_lookup 生产装配缺席**（P0-1）：原子查询工具该开放给 agent（按主人边界：
  单点查询=原子动作留工具），实际因 agent_factory 漏传 library 而**从未注册**——表达得出
  （工具 spec 在、描述在、LLM 被教"查参考书用 reference_lookup"），执行不了。
  **这是图灵完备性"能表达不能执行"的典型反例。**
- 校验一致性按钮（P0-2）：前端有入口，后端无路由。

### 1.3 状态完备 ✅（真实，且超出设计预期）

- 中间产物全部可落盘：章节双写（md 权威 + SQLite 镜像）、版本历史（note 带任务标识）、
  断点恢复（workflow node_output 持久化 + loop 迭代数续跑）、批级回滚（S138 三件套，
  防循环回滚实测绿）、压缩持久化回写（S26 压缩后上下文写回 store 跨重启有效）。
- 可逆性完整：单章恢复 / 批量回滚 / 二次回滚幂等，测试真实（test_scale_safety）。

### 1.4 组合完备 ✅（真实——最被低估的一条）

- workflow 引擎 5 节点（agent/script/approval/gate/loop）+ 集合遍历原语
  （collection_var/item_var + 断点迭代续跑）+ delegate 子 Agent（独立上下文工具循环）
  ——**有限原语 + 组合规则 = 任意流程**，图灵完备的组合支柱成立。
- 工具收编（S129-S135）正是此支柱的兑现：固定流程工具（拆书/批量/图谱抽取/信号提炼/
  会话摘要）→ 预置模板，原子动作留工具，新增复合能力不需新工具。

**小结：图灵完备四支柱三真一断（执行完备的两个断链都来自装配/接线层，非设计层）。**

## 二、人机交互五公理

### 2.1 "人=判别器" ✅（主循环结构里活着）

- 探索-判别双循环真实：探索者并行 N 路（asyncio.gather 独立上下文，strategy.py 差异化分派
  template/grow/user 三来源）→ 方向卡 → 用户/LLM 判别选优 → 固化 archive。
- 判别结果回灌：方向卡 → 项目档案（explore/archive）+ 设定档约束注入；伏笔/计划/推演
  均有人工确认闸门（approval 节点、plot 采纳、skill 草稿转正）。
- 但见 2.3：**"接受候选"这个最典型的判别动作，前端从未接线**——判别器公理在探索模块
  成立，在对话写作模块的"选卡"环节断裂。

### 2.2 能动性是刻度不是开关 ✅

- 档位五级 + 温度映射 + 记录集 CRUD + L2（AI 建议档位）/L3（自然语言生成档位，人工确认
  落库）双轴——真实且测试绿。S62 修正"启发式推断不自动应用"（用户主权）正确。

### 2.3 对齐闭环 ⚠️（主线活，支线断——子智能体实证）

**环 1 半通**：5 种信号（accept/modified/delete/rejected/negative/custom）中**只有 modified
真实活着**（稿纸保存/定点编辑后端自记，test_chapter_signals 绿）。前端 `reportSignal`
（api/signals.ts:13）**零调用方**——S75b 宣称的"选候选 accepted"从未接线；ExploreView/
PlayPanel/RolePanel 的候选选择都不发信号。章节删除故意不发（S132b 合理），但结果是
"操作即信号"哲学退化成"只有修改是信号"。

**环 2-5 全通**：refine_from_signals 后台调度真实（增量游标 + 多书遍历 + merge_add 防碎片，
test_signal_triggers_manual_refine 绿）→ MindPlanner 三分类规划真实（锁定优先/活跃度/本轮
相关动态选取）→ collab_block/mind_block/notices 注入真实（test_manual_notices 全链路绿）。

**环 6 半通**：/api/manual CRUD + 前端记忆视图存在，但**用户只能看+锁定，不能增删改内容**——
createManual/updateManual/deleteManual 前端零调用；"用户是最终编辑者"（DESIGN §6 宣称）
未完全落地。变更通知前端无消费组件（靠 agent 转述，prompt 级软约束）。

### 2.4 信任三通道 ✅

- 证据可溯：图谱实体带 first/last_chapter/weight/state 演化链（正文可回溯）；版本历史
  note 带来源标识；S116 事件溯源（record 轮快照可重放）。
- 改动可回滚：单章恢复 + 批级回滚（S138）。
- 跑偏可打断：steering 插话（S25 队列线程安全，当前轮工具结果后注入）+ followup 追问 +
  cancel 协作式取消（重试睡眠可中断 S22）。

### 2.5 摩擦前置 ✅（机制成立，但见 2.3 支线）

- 种子捕获 → 方向对齐 → 可观测写作的事前对齐路径真实（explore/intent 确认 → DirectionCard
  展示 → 写作）。双向黑盒解法（AI 倾向档案 bias + 可观测探索）真实注入。

## 三、大模型底层认知五事实

### 3.1 上下文稀缺 ✅（教科书式渐进式披露——子智能体逐块验证）

装配层 12 个注入块全部索引/摘要/精选级：skills 只注入名字+描述索引（超 100 字提示
skill_lookup 按需）、settings >20 条自动转索引、plot 只报数量+最近 3 条、心智锁定优先
限 5 条、场景记忆只注入一段话摘要、计划三章视窗。**无任何块注入整本书/全部章节/整个图谱。**
（轻微：skills 索引无体积上限、settings ≤20 条全量窗口偏大、CJK 粗算"高估安全"注释
与实测相反——安全靠 1.2 系数兜底。）

### 3.2 采样器非数据库 ✅（事实锚点真实）

- 图谱/设定档/正典章节三重锚点 + read_chapter 按需 + 检测网校验；write_chapter 意图模式
  的 references 由主循环精选原样引用（DEFAULT_SYSTEM 指令 + 工具原样不概括）。
- **但**：图谱抽取无后校验（见四.1：主角被误抽为"设定"无纠正机制）——锚点本身可能漂移。

### 3.3 干净调用 ✅（C 架构真实且唯一）

- _clean_write：上下文 = 写作系统提示 + 点名技巧 + 意图 + 参考，**无对话历史/无工具记录/
  无旧章节全文**（test_tools_writing 断言绿）。所有写作入口（write_chapter 意图模式）
  统一走此路径；直写（轻量）为显式降级。

### 3.4 指令遵循脆弱 ✅（注入分层索引化真实）

- 索引常驻（skills 名字+描述）+ 按需细看（skill_lookup）+ 点名注入（write_chapter skills 参数）
  三层次真实；S61 删自动匹配、S60 主循环点名决定——符合"把有限遵循力花在高优先级"。

### 3.5 模型无关 ✅

- 协议适配器（openai/anthropic/gemini/responses，S131）+ 多模型注册表 + 思考强度分级 +
  自然语言承载（工具描述/注入块/模板全为明确无歧义自然语言）——core 零依赖实证（第一部分）。

## 四、新增实质发现（子智能体 + 数据实证）

### 4.1 图谱抽取无质量后校验（数据实证：主角类型抽错）

真实库 data/anyspark.db：**主角"陈渡"被抽为 entity_type="设定"**（应为"角色"），
且 `last_chapter="环境描写：江心楼顶层"`（非章节名，是某次手动抽取时 chapter_ref 传了
内容片段）。根因：抽取 prompt 类型约束明确，但**模型判断漂移无后校验**——没有一个
"主角实体类型不符"的纠正机制；`POST /api/graph/extract` 接受任意 chapter_ref 字符串
（不校验是否真实章节）。图谱=跨章长期记忆，锚点自身漂移会连锁污染一致性校验。

### 4.2 图谱注入"已自动注入"过期宣称（子智能体实证：实质，且方向有害）

S58 已**有意停止**图谱常驻注入（封档：网络小说上下文贵），改为 graph_query 按需查。
但两处代码仍在宣称"已自动注入"：
- `schemas.py:717-718`（DEFAULT_SYSTEM）："更早的内容由【已固化事实】注入提供"
- `tools_domain.py:91`（graph_query 描述）："系统已自动注入当前时空点已知事实"

后果：**教 agent 不查证**——恰好放大 S58 封档预言的"AI 不知道要查什么就漏设定"风险。
S37 高频保底（为注入设计的数据层，weight/最近 2/3+高频 1/3）因注入已停而对 agent 实际
不可达，成了死数据层。**过期文案比缺失更危险：它把活工具引导向错误使用。**

### 4.3 检测网长章覆盖空洞（子智能体实证：实质）

ReviewEngine 每个检测者只喂 `text[:6000]`（reviewers.py:65），外层传 20000 也被二次截断。
**>6000 字的章节后半段，7 个检测者全部零覆盖**——"硬伤检测"对中长章名不副实。
另：DESIGN 宣称的"用户可增删骨架"只是注释（skeleton.py:44 无持久化/API/UI）；
"AI 动态生成检测项"未实现（checks 恒为静态骨架，三层"协作"实为三入口并存）。

### 4.4 检测网哲学本体 ✅（子智能体：建议非门禁全路径兑现）

写路径零挂钩（write_chapter 不调检测）、检测失败不阻断（ok=True 返回）、规则识别不了
明确告知不静默拦截、死约束已清（S62 删净 AI 味扫描/扣分，grep 零残留）、多检测者并行
真实（asyncio.gather 独立上下文 7 路）。**"航向系统非护栏"哲学活着。**

## 六、哲学终审

**写作领域图灵完备**：四支柱三真一断。断点在执行完备（两处装配/接线断链），
且都是"原子动作该留工具却未开放"——与主人划定的边界（原子查询留工具、复杂流程走
工作流）**相悖于现状**：reference_lookup 是原子查询却只在 workflow script 里可用（降级过头）；
而固定流程工具已正确收编。**边界执行偏了：该降的降了，不该降的也降了。**

**人机交互公理**：判别器公理、能动性刻度、信任三通道、摩擦前置**全部真实**；
唯一背叛是对齐闭环的"操作即信号"——5 种信号只剩 1 种活着，判别动作（选卡）恰恰是
用户最高频的"操作即信号"场景，却从未接线。**哲学在探索模块活着，在对话写作模块半死。**

**模型认知五事实**：上下文稀缺、采样器锚点、干净调用、指令遵循、模型无关**全部真实且
实现到位**——这是项目最扎实的哲学层。唯一的系统性风险是"过期宣称"：
S58 停止图谱注入后，两处文案仍在教 agent 相信"事实已注入"，这是**哲学实现后未同步
宣传**的典型，比没实现更危险（agent 被误导放弃查证）。

**一句话终审**：这个项目的哲学不是装饰——核心机制（干净调用/渐进披露/航向非护栏/
组合完备）在代码和产物里都活着，且真实 LLM 产物（32 章 + 图谱）印证了设计意图；
真正的稀释发生在**接线与文案层**：该接的线（选卡信号、说明书编辑、原子工具开放）
没接，该改的文案（图谱注入宣称）没改。**哲学被实现，但被实现得不够诚实。**
