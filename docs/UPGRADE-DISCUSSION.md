# AnySpark v4 升级讨论纪要（持续累积）

> 创建：2026-08-01 | 状态：**讨论中，未开始实施**
> 性质：战略讨论的累积记录。每次讨论后追加，保持上下文不丢失。
> 纪律：本文件只记录**已达成共识**与**待讨论议题**，不写实现细节（实施细节另立 plan）。

## 〇、讨论背景

- 项目：AnySpark v3.2.5，AI 小说创作引擎（Agent 自主循环 + 工具 + SQLite 图谱 + React 前端）
- 升级方向：**功能升级 + 架构升级 + 美学升级**（美学暂缓——未来换风格容易，关键在功能与交互）
- 另一个智能在负责遗留债务收尾（L 系列：mypy 清零/覆盖率/前端拆分），与本升级并行不冲突
- 核心锚点：**本项目最终最直接目的是 AI 写小说**

## 一、智能体设计原则（已达成，共 5 条）

1. **易用** — 用户上手成本趋近于零
2. **简洁解耦去限制化** — 不过多用人类规则限制智能体发挥；参考 pi 设计哲学（核心极简、功能外置、默认强大）
3. **平滑性** — 从"只有灵感的人"到"有完整规划的作家"都能用好，能力随使用浮现
4. **深度对齐** — 沟通成本不能大于写作成本；否则不如自己写
5. **极简方法论（最新确立）** — 最文本、最简单的方法优先；相信模型能力；自然语言承载；不过度工程。所有设计过"极简审查"
6. **逐步展开（交流基础假设）** — 无论用户脑中信息多少（只有灵感 or 完整骨架），人类交流总是**逐步、一句一句展开**的，不会一次性给出全部。推论：
   - AI 不期待用户一次给全信息，也不在用户未展开时自行脑补（抢跑）
   - AI 的每次输出都是"下一轮对话的准备"——信息交换是**小块、频繁、双向**的，不是大块一次性
   - 用户展开密度本身就是信号：说得细=图景清晰（AI 多执行），说得模糊=还在酝酿（AI 多引导）
   - 能动性 = 跟随展开节奏

## 二、对大模型与写作本质的认识（已达成）

- 大模型是**概率探索器**：默认走最大概率路径 → 高概率区 = 平庸区
- 优秀作品位于**奇异点**（低概率高价值区），默认采样走不到
- **抽卡（Best-of-N）收益有限**：只能改善平庸区内的排序，到不了奇异区
- 所以写作智能体需要的是**航向系统**（探索指引），不是**护栏**（禁令/模板/扣分）：
  - 死约束（禁令、模板、AI味扫描扣分）→ 把模型钉在平庸区，应退役
  - 活约束（意图、情感目标、读者体验、张力方向）→ 剪枝搜索空间，让探索聚焦奇异区
- 写作起点是**种子**：用户脑中已有新颖概念/激动场景 → 人机深度结合，非纯自主探索
- **双向黑盒是摩擦根源**：人不知道 AI 倾向（换模型还会变）、AI 不知道人的种子
  - 解决一：可观测的探索过程（用户能看到 AI 候选/理由/迭代，建立预期）
  - 解决二：**AI 倾向档案**——AI 主动暴露自己当前的倾向（"我这个模型写对话偏克制"），让用户能预测它，从而敢放手
- **体验目标：摩擦前置且递减**（北极星指标）
  - 现状：用户下指令→AI 闷头写→评审挑错→返工（事后纠错，摩擦峰值在最后）
  - 目标：种子交换→方向对齐→可观测写作（事前对齐，摩擦前置且递减）
  - 所有设计取舍以此为准：好交互 = 早期花小成本对齐，后期零返工；坏交互 = 前期不确认，后期大返工

## 三、功能规划（已达成初步共识）

### 决策标准：两方价值
> 用户不看 + 智能体也不用 = 删；**只要一方有较大价值就留**（人机结合项目，从两方考虑）

### 去留清单

| 功能 | 用户价值 | AI 价值 | 决策 |
|------|---------|---------|------|
| 叙事统计（Stats/Pacing/Heatmap/Metrics） | ✗ 作家不看 | ✗ 不需要 | 🔴 删 |
| AI 味扫描 | ✗ | ✗ 死规则反伤质量 | 🔴 删 |
| 记忆面板（手工分类表单） | ✗ 不想管理 | ✗ 对齐系统不需要 | 🔴 删（系统改造为对齐） |
| 知识库 | ○ 偶尔确认设定 | ✅ 写作一致性 | 🟢 留，退后台（AI 事实源） |
| 稿纸/对话/大纲/伏笔/剧情链/章节历史 | ✅ 核心 | ✅ | 🟢 留 |
| 资料库 | ✅ 扔素材 | ✅ 消化后参考 | 🟢 留，**补消化能力** |
| 文风/参考书 | ✅ | ✅ | 🟢 留 |
| 时间线/地图/灵感盒/推演 | ○ 部分类型刚需 | ○ | 🟡 降权，不进主导航 |

### 现状诊断（记录）
- 大量功能实现程度不一致：资料库、记忆系统几乎未实现
- 记忆系统现状 = 表单工具（手动分类偏好），非智能能力
- 资料库现状 = 存储 CRUD，无消化无关联

## 四、核心机制设计（已达成方向，细节待定）

### 1. 探索-判别双循环（写作机制）
```
用户一句话（意图）→ 航向解析（奇异点坐标大致在哪）
  → 多路探索（N 个差异化候选：换叙事策略/切入点/结构/文风偏移）
  → 判别（哪个最接近航向：LLM 判别器 + 人类在环选择）
  → 迭代收敛（选中方向 → 探索细节 → 再判别 → 收敛）
```
- 用户不是指挥者，是**判别器**（选择比描述容易）
- 每次选择同时写进用户模型（对齐）

### 2. 能动性协议（AI 做多少）
- 五级协议：0 只听写 / 1 执行+填肉 / 2 补全但标注 / 3 建议扩展 / 4 自主发挥
- AI 每轮可声明级别，用户一键点选修正；反馈自动调节（删=降级，接受=升级）
- 用户信息是**逐步展开**的 → AI 跟展开节奏走：种子阶段多问少做，方向确认后多做
- 长期看：能动性应是**心智模型的输出**而非独立旋钮——合作久了 AI 自然知道用户要什么程度，显式声明退场（只在冷启动/高不确定时出现）
- 隐式信号：修改频率、接受率、沉默、删改内容

### 3. 对齐系统（替代记忆系统）
- **路线选择：对齐优于记忆**。记忆路线有本质困难（存储-检索完备性无法达到，机械机制到不了人类记忆水平）；对齐追求"方向正确"而非"完整记录"，可持续逼近，且有容错性（错了纠正即新信号）
- 一条偏好陈述可指导几百次写作；百条历史记录每条只对特定时刻有用 → 信息密度决定对齐更优
- **用户模型 = 可解释偏好档案**（自然语言短句 + 来源 + 置信度 + 活跃度），模型无关（新模型可读，换模型不丢）
- **对齐信号全部来自操作**（选择/修改/删除/反馈），零打字成本，无表单
- 注入方式：每次会话注入，类似 pi 的 AGENTS.md
- 第一批信号来源（建议）：选择信号（方向卡选择）+ 修改信号（编辑器删改）
- **AI 的提问 = 不确定性信号**：只在"不知道该做什么"时才问，且问的是**关键歧义点**（"主角此时是恐惧还是渴望？"）而非泛泛问卷——提问从"烦人"变"必要"
- **提问频率 = 对齐进展的可视化**：用户看到的不是"AI 老问问题"，而是"AI 越问越少"——默契度增长本身就是产品体验

### 4. 低摩擦交互层（操作式表达）
- 打字 < 说话 < 脑内思考 → 把"描述"变"操作"
- 交互通道分层：点选(0.3s) → 滑块/旋钮(1s) → 拖拽(2s) → 画布操作(3s) → 打字(最后手段)
- 组件：能动性选择器、方向诠释卡、氛围滑块组、场景拼图板、候选卡堆、改写渐变条
- 每个操作 = 结构化对齐信号（操作即语义——打字需要解析语义，操作本身就是语义）
- **共同对象原则**：双方在同一对象上交流（概念卡/结构图/候选卡），而不是来回打字传达——卡片是"共享的稿纸"

### 5. 前端空间设计（美学方向，美术暂缓）
- 核心：把"并列的控制台"变成"有主角的创作台"——稿纸为主角，功能全保留
- 三层空间：稿纸（第一层，视觉主体）/ 写作上下文-候选卡·氛围·能动性（第二层，轻量浮现）/ 设定工具抽屉-知识·角色·时间线等（第三层，按需呼出，保留 Ctrl+数字）
- 对话从聊天窗口降为纸边批注；视觉收敛（荧光色→1主色+3语义色；字号层级重建；质感动效）
- 现有工程资产：19 面板分组导航、分屏、命令面板、快捷键、focusMode——保留利用

### 6. 结构模式模板（三层体系，讨论收敛）
- **核心认知**：大模型本身就是"不稳定的库"——训练数据内化了海量类型学知识（废柴流/升级流/双线/悬疑揭示/三幕/英雄之旅…），不需要从零外部建库
- **三层体系**：
  - L1 模型内化知识：免费、即时，解决"有没有"
  - L2 开发者默认库：精选少量高质量模式，解决个人用户大部分问题（内容工作是编辑能力非编程能力）
  - L3 进阶外部库：用户导入/平台库/社区共享——**商业化方向**（B 端平台有海量数据+版权协商简单，是深水区；C 端 L1+L2 够用）
- **统合方法：自然语言是唯一介质**——三层模式都以自然语言描述存在（+轻量元数据：粒度/位置/功能/来源，仅用于筛选注入）；模型自己读、自己融合、自己组合。不建组合引擎/匹配规则/冲突检测（都是强制护栏）
- **模板四要素元数据**：{ 粒度(全书/卷/章/场景/段落), 位置(开局/发展/高潮/结局), 功能(铺垫/主线/悬念/爽点/情感), 可变参数 }
- **边界（锁死）**：模板只做"探索方向的生成器"（粗粒度航向），绝不做"内容的框架"（填空=套路文，且模板被大量使用后自身变成新平庸区）；模板是起点，变体才是目标
- **稳定性**：模型内化知识每次生成会漂移 → 用户确认过的方向固化为自然语言记录（进项目档案/用户模型），可复现可引用；固化时机=用户确认，模板机制与对齐机制在此合一
- **提取能力边界**：LLM 能做"鉴定"（套人类已命名类型学框架+提取量化特征——网文社区已完成的命名是公共知识），做不了"发明"（发现人类未命名的新奇异结构）；人类提供分类学，LLM 做标本鉴定
- **交互红利：流派术语=共同语言**——候选卡直接用术语标注（"废柴流开局·反差铺垫"），懂网文的作者秒懂，术语卡代替描述，降低沟通成本
- **架构含义**：模式库抽象为独立层，数据源可插拔（模型内存/默认库/用户导入/平台库）
- **探索方向三来源混合场（模板不独占）**：探索候选必须混合三个来源，否则小众/原创型用户被隐形模板墙框死：
  - ① 模板派生：从三层模板体系生成的方向（服务小白/快速起步）
  - ② 作品内在生长：完全从种子+已有内容自然推导，不走任何模板（服务原创性需求；纯靠模型对这部作品的理解，不依赖库）
  - ③ 用户指导：用户脑中非常规约束直接作为航向（"没有情节只有氛围"）（服务专家/有明确想法的人）
  - 候选卡永远混合三来源（例：4 张卡 = 2 模板 + 1 自由生长 + 1 用户直觉）；用户选模板还是选自由卡 → 对齐信号 → 未来混合比例自动调整（模板占比=用户模型的输出）
  - 一句话：**模板是探索的脚手架之一，不是道路本身；道路由三来源共同铺成**

### 7. 多智能体探索（探索-判别的实现形态）
- **动机**：同上下文多选项存在伪多样性（一个模型给 4 个选项会被自己第一个思路锚定、向中间收敛）；上下文隔离 → 真多样性（multi-prompt sampling / ensemble 有理论支撑）
- **现有落点**：现有子 Agent 系统（5 种类型、独立上下文派生）就是天然基础，不是新造架构
- **流程**：
  ```
  [意图理解者] 理解种子+用户要求 → 对齐确认（先给用户看，摩擦前置最便宜的纠错点）
        ↓ 确认后
  [探索策略集] 主 Agent 定义差异化分派（按叙事维度/模板/自由/用户指导分派）
        ↓ 并行（asyncio.gather，轻量上下文）
  [探索者 ×3-4] 各自产出方向卡（带术语标注）
        ↓
  [用户判别] 选/杂交 → 反馈信号 → 定向再探索（多轮）
        ↓
  [固化] 选中方向落盘进项目档案
  ```
- **8 项约束（讨论确认）**：
  1. 成本控制：探索者用轻量上下文（种子+关键设定摘要+方向指令，不带全量图谱）；并行调用时间≈单次；探索层可跑 Flash，Pro 留给写作
  2. 轻量优先：探索者多数是单次 LLM 调用，不需要完整 while-true 循环+工具；只有需查资料的探索者才给工具（避免过度工程）
  3. 多样性不自动保证：主 Agent 先定义探索策略集（情节驱动/角色驱动/氛围驱动/结构实验/模板/自由/用户指导…），每个探索者拿不同维度指令
  4. 意图理解者产出物是"对齐确认"而非方向——先确认理解再放探索者跑（两阶段：意图确认→方向探索）
  5. 多轮循环：单轮 4 卡可能都不对，用户要的是杂交（"A 设定+B 结构"）→ 定向再探索
  6. 选中方向结构化摘要固化进项目档案（探索者隔离，主 Agent 需要记住方向细节）
  7. 轻量上下文必须含"已固化设定约束"（一句级：女主=医者）——探索自由但不得撞已固化的墙
  8. 展示顺序效应：多卡随机排序/分组展示，避免位置偏见污染对齐信号

### 8. 用户自定义规则（用户边界 + 两级实现）
- **区分：用户自定义边界 ≠ 系统护栏**
  - 系统强加规则（AI 味扫描扣分）= 护栏 → 删
  - 用户自己要的规则（"我不要破折号"）= 用户主权 → 必须支持
  - 去限制化去的是"系统的限制"，不是"用户的限制"
- **动机：用户需求加不完**（破折号/禁用词/格式习惯…）→ 靠"让系统自己能扩展"解决，而非预定义所有规则
- **两级实现**：
  - ① 轻量规则编译器（默认，极小）：用户自然语言规则 → 内置编码 agent 生成检测函数（正则/简单逻辑）→ 注册进检测网用户自定义层。只读纯文本处理，无文件系统访问，安全风险极低（例："不要破折号" → 生成"文本中——出现次数"检测）
  - ② 编码扩展包 anyspark-codex（可选，不默认装）：需要复杂自定义工具/分析时启用，可打包 pi 类编码 agent，沙箱执行；按需安装，核心保持极简（YAGNI）
- **用户自定义检测项三种来源**：选项卡点选 / 自然语言描述（→轻量编译器） / 复杂规则（→编码扩展包）
- **关于嵌入 pi 的评估**：方向对但完整 pi 跨语言集成成本高（Node/Python）+ 能力大部分用不上；降级为可选扩展包，默认提供轻量编译器

### 9. 检测网（三层协作生成，替代死护栏）
- **为什么以往检测网失败**：静态规则只能覆盖已预见的错；误伤（分不清合法创作与错误）；平庸标准（合规≠写好）
- **三层协作生成**：
  - ① 系统骨架（第一性原理，硬编码默认值，用户可增删）：一致性 / 动机因果 / 情感连贯 / 信息流（悬念揭示） / 结构节奏 / 预期管理（吊起的期待兑现） / 主题连贯
  - ② AI 动态生成：模型针对当前作品+阶段具体化检测项（"第3章自称孤儿第7章有母亲——矛盾"），检测项=自然语言、随作品演化
  - ③ 用户自定义：用户毒点/关注点（机制 8 实现：点选/自然语言/复杂规则）
- **多检测者并行**（复用多智能体）：一个查一致性/一个查情感弧/一个查信息流……轻量，汇总成审读报告
- **建议而非门禁**：结果是报告+建议，不做"不达标暂停"；硬伤（设定矛盾/断章失忆）才标红提醒
- **定位：编辑的第二双眼睛**（帮用户发现盲点），不是审查者；决定权在用户
- 与删掉的 AI 味扫描的本质区别：帮把故事写好（第一性原理） vs 别像 AI 写（合规）
- 检测时机（倾向，待实施时定）：章末轻量 + 用户喊深度，不打断写作
- 与机制 8 衔接：用户自定义层即用户自定义规则

### 10. 资料消化（补全资料库能力）
- 现状：资料库=存储 CRUD，无消化无关联（功能规划已定"补消化能力"，此机制即实现）
- 流程：
  ```
  用户上传材料 → [入库消化·自动] 模型生成材料摘要卡（主题/要点/关键设定/涉及角色/术语）
    → 摘要卡自动关联图谱实体（角色/地点/事件）→ 材料原文保留（可查全文）
  写作/探索时 → [按需检索]（FTS/图谱关联/模型判断）→ 注入摘要卡（省 token）
    → 模型需细节再查全文 → 引用处标注来源（防串书）
  ```
- 关键设计：
  - **摘要卡是核心**：入库时模型压缩成摘要卡，写作注入摘要卡而非原文；信息密度高省 token
  - **图谱关联**：摘要卡提到的人物/地点自动链接知识图谱 → 写作时"检索当前时空点已知事实"自然带上相关材料，图谱=统一关联枢纽（无需单独材料检索机制）
  - **用途标注**（衔接现有参考书用途隔离）：文风参考 / 设定事实 / 两者——防材料角色串进正文
  - **来源标注**：正文引用材料可追溯
- 分工：资料=私有素材（作品世界/参考）；模式库=结构模板（故事组织）；说明书=用户偏好（怎么写）——三者并列不重复
- 与现有衔接：参考书功能（文风/事实隔离）即资料消化的一种形态；MaterialsPanel 是存储层——升级=加摘要卡+图谱关联+按需注入

## 六、T2：种子→作品完整交互流程（已确认）

> 原则贯穿：摩擦前置（每步先对齐再前进）、操作即表达（打字最后手段）、按需深入（用户到哪层探索到哪层）、展开密度即信号（输入越完整，低级探索越自动跳过）
> 核心循环只有三个对象：**概念卡（理解）→ 方向卡（选择）→ 稿纸（产出）**，其余都是变形

### 阶段 0 · 进入（几秒）
- 唯一入口："这本书你想写什么？"——一句话 / 粘贴完整大纲（自动消化，不强制分卷建章）
- 平滑性：入口只有一个，能力随输入密度自动分级
- **专家路径**：输入密度高（粘贴完整骨架）→ 自动跳过低级探索，直接进图谱/写作

### 阶段 1 · 种子捕获（第一次对齐，1-2 分钟）
- 用户自由说种子（画面/概念/情绪/设定都行）
- AI 不立即干活：① 复述成**概念卡**（画面核心/情绪基调/类型直觉/种子位置(开篇?/高潮?/结局?)，可点选修正）② 只问 2-3 个**关键歧义点**（AI 提问=不确定性信号，只问影响方向的问题，如"两人是熟悉还是陌生？"）
- 概念卡=共同对象，双方在它上面交流；种子位置确认（创作动力≠结构支点）；能动性默认 0-1 级

### 阶段 2 · 方向探索（几分钟）
- 多智能体并行（意图理解者→探索策略集→探索者×3-4 轻量），产出**混合三来源**方向卡（2 模板+1 自由生长+1 用户直觉，带术语标注）
- 用户判别：选它 / 感兴趣展开（定向再探索多轮）/ 再来一批；**"我已有想法直接写"出口**
- 选中方向→结构化摘要**固化进项目档案**（含已固化设定约束，后续探索不得撞墙）
- 对齐信号：选模板 vs 自由卡 → 学习用户类型 → 未来混合比例自动调整

### 阶段 3 · 关键点图谱（作品级规划，可选深入）
- AI 基于概念卡+方向生成图谱草案（主线冲突/角色弧/情感核/世界规则/情绪峰值/伏笔/节奏——网状非大纲）
- 用户操作：增/删/改/标"我在意/不需要"——操作即对齐信号，关注点跟随在此学到
- **图谱=跨章长期记忆**：每章写作时注入其当前状态（哪些推进/哪些没收），从规划工具升级为活的长期记忆；可演化非一次性工程
- 不强制：小白可跳过直接写作，专家可深耕；分层探索（作品级→章级→场景级，用户说到哪层探索到哪层）

### 阶段 4 · 按需深入
- "我想写第一章"→只探索第一章；"理下第 3-5 章"→卷级；"直接写"→进稿纸。不为未写的部分付探索成本

### 阶段 5 · 写作（主体，稿纸为中心）
- 用户在写：AI 后台工作（记住设定/一致性检查，不打扰）
- "你写这段"：声明级 3-4 → **方向声明**（"我准备写：主角推开玻璃…"）→ 用户 0.5s 确认/调级 → 探索-判别生成 → 候选卡 → 选
- **方向声明限定**：只在方向不确定/能动级别变化时出现，确认后连续写作不再重复确认（默许=授权）
- 卡壳：建议卡（可拖入稿纸或丢弃，从不直接改稿）；选中段落要改：候选改写卡堆+渐变条（保原味↔大幅改）
- 连贯性后台化：知识库/设定约束 AI 自动维护；撞已固化设定→温和提醒卡（非弹窗打断）

### 阶段 6 · 一章完成（轻量收尾）
- 自动：更新关键点图谱（哪些推进了）+ 一致性摘要卡（一句话非强制）+ 下一章衔接提示（"建议推进角色弧，展开吗？"）
- 不自动评审：评审降为按需增强包，用户喊"帮我看看这章"才出现（重构为判别器：选方向不挑毛病）

### 贯穿：对齐积累
- 每次点选/修改/删除/标注/调级→对齐信号→用户模型更新→注入后续全部探索与写作；信号带置信度（单次操作不产生强结论）；提问频率递减=默契度增长的可视化

## 七、T3：对齐系统与 Agent 循环的集成（已确认）

### 双轨提炼（每次会话结束时自动运行）
- **摘要器**：对话 → 场景记忆（发生了什么/进行到哪/做过哪些决定）→ 项目档案（承担延续性——摘要擅长的）
- **提炼器**：对话+操作 → 偏好条目（用户倾向什么/什么有效/什么雷区）→ 用户模型（承担对齐——摘要不擅长但对齐需要的）
- 下轮会话开头：AI 主动展示 1-2 条"我从上次学到的" → 用户确认/纠正/丢弃（确认升置信度，纠正即修正）
- **pi 设计评价**：会话持久化+compaction+AGENTS.md 的骨架正确，但缺"自动提炼用户"环——编码场景用户自己写 AGENTS.md 可行，写作场景用户不会写偏好文件，偏好必须自动捕捉

### 说明书形态（对齐的载体）
- 本质：**可读性高的自然语言文档**（像说明书，多条目），系统自动维护，用户是最终编辑者
- 跨模型：纯自然语言，任何模型可读，文档开头带"使用说明"
- 条目元数据：来源（自动提炼/用户手写）+ 置信度 + 活跃度 + 锁定状态
- 用户编辑权：直接改文字 / 删除 / 新增 / **锁定**（锁定条目系统永不自动改）
- 解决：摘要污染（来源标注）、用户不知系统如何看自己（可读）、提炼错误（可改）、无法操作（条目化）、用户主权（锁定）

### 说明书分层（项目级主体 + 全局级极小化）
- ① 项目说明书（每本书，**主体**）：关键点图谱/设定约束/方向固化/进展/书内偏好（用户大多数偏好是项目内的，不串书）
- ② 全局说明书（**极小化**）：硬习惯/雷区/沟通方式——仅用户确认的跨书稳定条目
- ③ 会话层（临时，不落盘）
- 继承：注入优先级 项目级 > 全局级；项目级永远可覆盖全局
- **跨层升级需用户确认（防跨书污染）**：系统发现多本书重复偏好 → 建议升级全局（"三本书都删血腥，设为全局雷区？"）→ 用户确认才进
- 校准仪式：用户偶尔审查说明书 = 对齐校准（看到错的就改）；审查本身可作低频可选功能

### 对齐闭环（三层）
自动提炼（建议）→ 说明书载体（可读可改）→ 锁定机制（用户主权）

## 八、T5：模型策略（已确认）

- **模型无关性为硬原则**：所有功能不依赖特定模态/特定模型，换模型功能不崩，只是质量因模型而异
- **实现方式**：系统内部一切承载物（说明书/档案/摘要/探索指令/方向卡/提炼结果/偏好条目）全部是**明确、无歧义的自然语言**——功能依赖"自然语言协议"而非某个模型能力
- **模型是插槽，不是依赖**：任何模型接上都能跑全部功能
- **Pro/Flash 双模型分拆降级为可选性能优化**（Pro 创作/Flash 抽取是成本手段，非功能依赖）；单一模型也完整运行
- 与既有设计自洽：说明书/摘要/探索指令/方向卡全部已按自然语言设计

## 九、T4：重写策略与资产复用（已确认）

> 判断（人月神话视角）：代码是"死山"——概念完整性已死，修补无法恢复统一性。结论：**重写核心 + 复用资产**，不做全盘推倒，也不做死山修补。

### 依据
- **概念完整性 > 功能数量**（最强论点）：死山由多个 AI 会话拼成，风格混杂实现不一，修补只能延续不一致
- **AI 时代特殊性**：代码是 AI 写的 → 重写成本从"人月"变"AI 时间+认知成本"，重写可行性根本性提升
- **Plan to throw one away**：理解已远超代码（设计纪要完整），代码是过时的第一版
- **第二系统效应受控**：v4 设计核心=去限制化+删功能+极简，纪要反复过"极简审查"，防膨胀
- **没有银弹**：重写本身不是银弹——"重写+新架构+资产复用"才是

### 可复用资产清单
- **数据**（15 本书 / SQLite 图谱 / JSON 章节会话）：保留格式或写迁移脚本，绝不丢
- **测试套件**（700+ 用例）：**规格资产**（行为契约），重写时对照验证，不是丢弃
- **打包/CI 基建**（Windows/macOS、CI、pre-commit、启动脚本）：原样保留
- **前端组件**（TipTap 编辑器、时间线/关系图/地图可视化、api/http/sse、主题系统）：保留，主界面重排复用
- **设计模式**（Agent 循环思想、工具注册、Book Lock、重试/压缩、事件总线）：延续到新架构

### 重写清单（按 v4 设计，不背死山认知债）
- Agent 循环本体（去护栏耦合，接探索-判别）
- 工具系统（降权、按需暴露）
- 对齐系统（全新）、探索引擎（全新）、交互层（全新）
- 前端主界面（创作台重排）

### 删除清单（代码不迁移）
统计仪表盘、AI 味扫描、记忆表单、创作宪法/叙事约束等护栏

### 路径：二次项目（修正：放弃绞杀榕渐进迁移）
```
新系统独立建设（绿地，按 v4 自由生长，不兼容旧协议）
        ↓
旧系统保持可用，直到新系统能切换
        ↓
切换时一次性导入数据（复制/转换脚本，不做"迁移方案"）
        ↓
旧系统退役（可选保留只读）
```
- 每步测试对照行为契约，数据（15 本书）切换时一次性导入，绝不丢
- **理由**：数据全是自然语言/JSON（章节/图谱/会话），导入成本极低；为迁移设计复杂方案=过早优化（YAGNI）必然返工；渐进迁移复杂度全花在"兼容旧系统"上，二次项目不需要兼容，只需读取数据
- 早期不设计迁移方案：新系统数据形态未定时写迁移=废的
- 资产照常复用：测试套件（行为契约）/基建/前端组件/设计模式
- 并行期维护成本可控（旧系统大部分是"删"而非"迁"）
- 可逆性：任何一步失败可回退到旧系统

## 十、T1：多包架构核心原则（已确认）

> 复现 pi 的逻辑（核心极小+功能外置+自然语言协议），不复现代码（技术栈/语义完全自主）

### 包划分（按机制切，天然解耦）
```
anyspark-core     内核包：Agent 循环、极简工具集、存储接口（不依赖任何包，单向依赖）
anyspark-explore  探索包：意图理解/探索策略集/多智能体探索者/定向再探索
anyspark-align    对齐包：说明书（分层）/提炼器/摘要器/注入器/信号采集
anyspark-template 模式库包：三层模式（模型内存/默认库/外部库接口）
anyspark-ui       前端包：创作台（稿纸/卡片/滑块/抽屉）
anyspark-desktop  桌面包：打包与生命周期
```

### 核心原则
- **功能层全部可解耦**：AI 时代功能=prompt+工具+数据处理，全可外置；核心不“知道”功能存在，只负责读提示→执行工具→回填结果
- **协议层必须内聚（且极小）**：循环（while-true）、工具调用协议、上下文管道（消息结构/提示组装/token预算）、事件协议（注册钩子，核心只发通用事件+类型化负载）、存储接口（实现可换）
- **能动性/探索-判别/事件扩展均外置**：能动性=提示注入（对齐包写，核心只读）；判别=工具结果返回；事件=注册钩子
- **YAGNI：不为用不到的功能建接口**——先建 core+align+explore+ui（v4 主路径），其余（模板 L3/评审包/Autopilot 包）按需后补；解耦点即接口，有设计成本，勿极端化
- **与既有结论自洽**：二次项目独立建设（T4 修正）、包间自然语言协议+事件（T5 模型无关）、商业化分层（免费 core+付费增强）

|---------|---------|------|
| 对齐生效 | 修改率（用户改 AI 产出的比例随时间下降） | ↓ |
| 对齐生效 | 提问率（AI 每千字提问递减） | ↓ |
| 对齐质量 | 确认/纠正比（说明书条目确认占比升） | ↑ |
| 探索质量 | "再来一批"频率（频繁=探索差） | ↓ |
| 检测有效 | 建议采纳率 | ↑ |
| 摩擦降低 | 打字/操作比（输入 token vs 点选拖拽） | ↓ |
| 完成度 | 种子→第一章完成率（漏斗） | ↑ |
| 留存 | 回访率/每会话写作字数 | ↑ |
- 核心只看三个：修改率 / 提问率 / 完成率，其余辅助

### T8：L 系列边界（交接文档细化）
- 可动（照常）：与 v4 无关清理——死代码/覆盖率/前端拆分（保留组件）/mypy 类型修复（只修不重构结构）
- 不可动（v4 专用）：新包目录 anyspark-*（core/align/explore/…）、检测/对齐/探索新增模块
- 条件可动：agent_loop/tool_registry/数据层——类型修复 OK，禁止重构行为
- 冲突规则：遇到与 v4 方向冲突改动（评审/宪法/扫描）→ 停下问主人
- 交接时点：v4 开工（阶段 0 启动）→ 核心文件冻结，L 系列转纯清理

## 十二、技术选型与仓库结构（已确认）

- **名字**：继承 AnySpark（v4.0.0 起步）
- **技术标准**：AI 擅长写 / 用户方便部署 / 方便升级打包
- **选型**：
  - 后端：Python 3.11+ / FastAPI / SQLite（嵌入式，用户零安装数据库）
  - Python 包管理：uv workspace（monorepo 多包，锁文件清晰，AI 极熟）
  - 前端：React 19 / TypeScript / Vite / Tailwind 4 / TipTap（编辑器）/ Zustand（轻量状态）/ npm（单应用）
  - 桌面壳：轻量自研（Python WebView）+ PyInstaller 打包（不引入 Electron/Tauri 重型依赖）
  - 部署：源码一条命令（uv run + npm build）；用户=桌面壳包双击即用
  - **升级方便的关键**：数据在用户目录（data/），版本升级=替换程序，数据不丢
- **仓库结构（单仓 monorepo）**：
  ```
  anyspark/
  ├── pyproject.toml        # uv workspace 根
  ├── packages/  core/ explore/ align/ template/ desktop/
  ├── frontend/             # React 创作台（npm 单应用）
  ├── data/                 # 运行时用户数据（.gitignore）
  ├── docs/                 # 设计文档（纪要拷入为初始文档）
  └── tests/
  ```
- **纪律延续**：禁 git add -A / data 不入库 / commit 编号 / 依赖 pin+锁文件
- **实施**：由 AI 编写（主人确认）
