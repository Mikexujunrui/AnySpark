# v4 蓝图与使用反馈集成说明

状态：评审分支 `codex/v4-feedback-integration`，基线 AnySpark 3.2.7；完成本地回归后提交原作者审查，暂不作为正式版本发布。

## 取舍原则

本线采用 v4 蓝图的“手稿中心、渐进披露、探索—判断循环、低摩擦交互”，但不把所有高级能力删除。时间线、关系图、评审团、参考书、Skill、创作宪法和 Auto 对当前续写工作流有真实价值，应保留为可选增强包；默认界面可以简化，能力本身不能消失。

## 近期群反馈归纳

以下只记录产品需求，不保存群成员身份或聊天原文：

1. 长篇分段不仅限制单轮字数，还必须限制本轮能消费的剧情范围，避免用 2000 字仓促写完 8000 字情节。
2. 章节间常出现时间、地点、人物状态和行动因果断裂；时间线应能表达主时间范围与“数日前”等支线时间，并参与写前导航和写后校验。
3. 需要可复用的剧情规范/剧情库，减少每章重新讨论同一种节奏、冲突和展开方式造成的 token 浪费。
4. 首章前约 200 字需要独立体检，但不能把所有题材强制套成同一种强冲突开篇。
5. 文风库和评审团需要基于真实样本识别 AI 八股、表达符号滥用、情感空洞、角色声音同质化等问题。
6. 写作交互需要明确区分沉浸式扮演、作者视角共同创作和混合模式，并明确剧情控制权归用户。
7. 大型参考书的拆解、上传、分析必须分块、可恢复并显示真实进度，不能长时间无响应后才报错。
8. 导出完成后必须显示实际路径；桌面版宜默认使用用户可预期的位置或弹出系统保存选择。

## 已实现

- 能力包按当前任务动态披露，减少模型同时看到过多近似工具导致的竞争与 token 浪费。
- Skill 作为带步骤状态的工作流运行，阻止未执行工具却文字声称完成。
- 长章按剧情合同分段，每段有目标、结束状态和禁止提前消费的后续事件；越界文本不会先闪现再被悄悄覆盖。
- 原著文风评审可读取当前正文、知识库与参考书证据；参考书事实和文风样本按用途隔离。
- 自主编辑、空/重复补丁熔断、拒答不落盘、首章短片段评审和 macOS 无残留构建。
- 章节交接卡升级为开头/结尾结构化状态，只有两侧都有高置信原文证据时才报告冲突；写作准备与正文生成共用同一份紧凑上下文。
- 时间线增加主时间、回忆、预叙、同期支线四层以及绝对/相对时间、来源证据和置信度；章节时间范围在时间线页集中展示。
- 新增用户显式启停的剧情规范库，启用规则以受限长度注入正文写作，停用项不消耗模型上下文。
- 参考书全量分析支持后台任务、固定输入分块指纹、逐维度缓存、持久进度和失败/重启后续跑。
- 桌面版导出使用系统保存面板并回显实际路径；浏览器模式明确提示由浏览器下载目录决定。
- `.spark` 归档携带交接卡、剧情规范和证据化时间线；修复跨电脑导入到新书籍 ID 时图谱数据被过滤的问题。

## 本阶段已完成

1. 章节“交接状态卡”：写前读取上一章结束时刻、地点、伤势、持有物和未完成动作；写后只对双向高置信证据支持的差异报警。
2. 双层时间线：章节主时间范围＋回忆/信件/数日前等故事时间支线，所有相对时间保留来源和置信度。
3. 剧情规范库：保存可复用的节奏/冲突/视角/禁用套路模板，用户显式启用后才进入正文上下文。
4. 大参考书任务化：HTTP 请求立即返回任务，后台建立固定大小输入检查点，逐维度缓存并支持失败或应用重启后续跑。
5. 导出路径可见化、桌面原生系统保存面板，以及浏览器模式的下载路径说明。

## 后续候选

- 把参考书分析从“输入分块检查点＋逐维度缓存”继续细化为可合并的逐块统计结果，进一步降低超大作品的峰值内存。
- 为交接冲突增加人工确认/忽略状态，避免同一条已知冲突重复提示。
- 待用户提供正反例语料后，加入可引用证据、可测试规则的反 AI 八股评审专家。

## 暂缓

- 反 AI 八股训练语料：先等待用户提供正反例文本，再做可引用证据和可测试规则；不凭模型直觉编造“人类文风标准”。
- 大规模 UI 重排：与原作者 v4 可能高度冲突；本分支只增加独立面板和兼容字段，待 v4 落地后再人工合并导航结构。
- 自动重写低分章节：评审默认只指出差距，不因评分低自动覆盖正文。

## 与原作者 v4 的合并方式

不长期维护一条巨大分叉。当前线先在 3.2.7 上形成小提交，并按“稳定性修复、文学工作流、macOS 构建”分组。作者 v4 可用后，新建以 v4 为底座的整合分支，通过 `cherry-pick` 选择低冲突提交；对时间线、导航和界面等重叠模块重新实现或人工合并，不把旧文件整块覆盖新架构。
