## 3. 未实现 ❌（按优先级排序，含规格出处）

### P0 — 知识图谱（最高，AI 事实源根基）
- **规格**：§8 数据设计第 3 项"知识图谱（SQLite）：实体（角色/地点/事件）/关系/时间线——AI 事实源，写作时'当前时空点已知事实'检索注入"
- **模型局限弥补表**："记不住长篇小说事实 → 知识/记忆基础设施：图谱数据库、FTS 全文检索"
- **依赖它**：资料摘要卡图谱关联（机制10）、检测确定性校验（设定冲突图谱比对）、"当前时空点注入"
- **现状**：完全无实体/关系/时间线表；写作时无事实检索注入
- **提示**：旧系统（自研高级时间线辅助写作agent）有 novel.db 图谱 schema 可作思想参考（勿复刻代码，见 §10）

### P1 — token 预算 + 两阶段压缩（长书刚需）
- **规格**：上下文管道"token 预算"、模型局限弥补"上下文窗口有限 → prune/summarize 两阶段压缩"
- **现状**：仅 `max_tokens` 输出限制 + 检测/探索手工截断 `[:6000]`/`[:4000]`；无预算计算、无历史压缩
- **依赖它**：长篇小说（几十万字）不压缩必然超窗口

### P1 — 能动性协议（机制 2，0-4 级）
- **规格**：五级协议（只听写/执行填肉/补全标注/建议扩展/自主发挥），AI 每轮声明级别 + 用户一键点选 + 反馈自动调节 + 温度映射
- **现状**：无任何实现；写作时无档位控制
- **前端**：需能动性选择器（机制 4 组件之一）

### P2 — SSE 流式传输
- **规格**：A 类硬编码"事件协议（SSE 类型/注册钩子）、交互基础（SSE 传输）"
- **现状**：core `events.py` 事件协议有，但后端 HTTP 全量返回，无 SSE/流式；前端无 EventSource
- **价值**：长文生成不流式 = 用户干等 20s+（当前 chat 请求实测 10-40s）

### P2 — AI 倾向档案（双向黑盒解法）
- **规格**：§2"AI 主动暴露当前倾向：'我这个模型写对话偏克制'"；半硬编码清单含"AI 倾向档案"
- **现状**：无
- **价值**：让用户能预测 AI、敢放手（摩擦前置）

### P2 — 确定性校验（时间线冲突/设定冲突/伏笔匹配）
- **规格**：模型局限弥补"不稳定 → 确定性校验：时间线冲突检测、设定冲突检测（图谱比对）、伏笔匹配（确定性部分）、章节结构校验"
- **现状**：检测网硬伤完全依赖 LLM 判断，无代码级确定性兜底
- **依赖**：知识图谱（比对基础）

### P3 — 流程基建（超时熔断/重试/指数退避）
- **规格**：模型局限弥补"不会自己调度 → 任务队列、并发控制、Supervisor、指数退避重试、超时熔断"
- **现状**：有 `max_tool_iterations` 防死循环，但无请求级超时/重试

### P3 — 安全底线（幻觉检测 fake_tool/fake_write、越界保护）
- **规格**：A 类硬编码"安全底线：幻觉检测 fake_tool/fake_write、越界保护"
- **现状**：无

### P3 — 工具范围扩展（文件读写/文档解析 txt-docx-md/多格式导出/网络搜索）
- **规格**：模型局限弥补"做不到的动作 → 工具执行：文件读写、文档解析、多格式导出、网络搜索"
- **现状**：仅 3 个写作工具（list/read/write_chapter）

### P3 — 低摩擦交互层组件（机制 4）
- **规格**：氛围滑块组、能动性选择器、候选卡堆、场景拼图板、改写渐变条；"操作即表达"
- **现状**：探索面板（种子输入+点选）+ 说明书面板；其余无
