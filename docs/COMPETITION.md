## 2. 面向校园场景的即用功能（本次比赛主打）

### 2.1 学术检测规则包（S246 新增）
- **形态**：不是硬编码第二骨架——学术七项（术语一致性/论断证据/结构完备/逻辑链条/
  语言规范/数据一致/诚信自查）作为**内容数据**借 S195 用户骨架通道自举：
  可查、可删（删了不复活）、可恢复（重新物化），与预置模板的 builtin 形态同型
- **生效范围**：`/api/check` 与 agent `check_text` 工具同源生效（此前 agent 自查
  看不见用户自定义项，S246 补齐数据接线）
- **诚信立场**（差异化加分项）：「诚信自查」项明确"辅助自查、不代替作者判断"——
  主动把诚信护栏做成功能，而不是回避

### 2.2 「审稿回复」预置工作流（S246 新增）
- 逐条意见 → 意见解读/回应策略/修改方案/回复措辞 → 汇编完整回复信草稿
- 全部复用既有原语（list_split 清单切分 / loop 遍历 / accumulate 累计 / agent 汇编），
  **模板即数据**：用户改节点指令即改回应风格，零代码
- 草稿给人过目后自行采纳（回复信是作者署名的文档——闸门前置到采纳）

### 2.3 既有能力直接复用的校园场景
- 竞赛申报书：结构化长文 + 批量按意见修改 + 心智系统学导师/评委偏好
- 课程论文/读书报告：资料库双态笔记（AI 提炼 + 原文冷藏）+ 交前自检
- 校园新媒体：批量改写一稿多平台；心智=账号人设一致性
- 讲稿/辩论：play 推演引擎模拟评委提问/对方质询

## 3. 诚实缺陷清单（边界与差距）

| # | 缺陷/边界 | 现状 | 补全计划 |
|---|---|---|---|
| D1 | **小说语境固化在 prompt 层**：write_chapter/拆书七维/学习审查等指令按小说措辞写死 | 机制已分离、内容未参数化 | **文体 profile**（仿模型 registry：-fiction/-academic/-report 配置化）——一次投入解锁全部非小说方向 |
| D2 | 学术硬缺口：无引用管理（GB/T 7714/BibTeX）、无公式渲染、无 LaTeX 导出 | 未做 | 按需引入，比赛演示不依赖 |
| D3 | 文献获取弱：search_web 面向通用搜索，无 arXiv/知网对接 | 未做 | P5 扩展工具机制可挂载外部 API（人工批准生效）——架构已有，连接器未写 |
| D4 | 查重/AIGC 检测不做（也不应做） | 设计决定 | 定位为辅助工具；诚信自查项提供反向价值 |
| D5 | 检测网 AI 检测项消耗模型调用（每项一次），长文成本随项数线性 | 并行检测+分块已有 | 规则包项数控制 + 轻量模板规则（compile_rule）优先 |
| D6 | 前端面板按"章节"组织，非小说文体语义略错位 | 可复用（章节=文档单元） | 文体 profile 后改名/换皮即可 |
| D7 | 伏笔/叙事树等面板对学术场景无意义 | 不影响核心链路 | 不隐藏（演示小说能力即卖点），文档说明定位 |

## 4. 比赛前已完成的真实补全（S246）

1. **学术规则包**：7 项学术检测项种子入库（`check_store.py` 自举，幂等 + 尊重删除 +
   恢复重新物化）；`tools_check` 改用合并骨架（与 `/api/check` 同源）
2. **「审稿回复」模板**：第 10 个预置工作流（`seeds.py`），复用 list_split/loop/
   accumulate/agent 四原语，零新机制
3. **`list_split` 通用原语**：清单切分机制（JSON 数组/逐条文本 → 遍历源），可复用于
   任何批量语义场景
4. 测试：`test_builtin_packs.py` 4 用例（种子/幂等与删除尊重/工具合并骨架/模板 e2e）
