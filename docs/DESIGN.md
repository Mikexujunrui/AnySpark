## 0. 项目概述

**AnySpark v4** 是一个 AI 小说创作引擎。**最终最直接目的：AI 写小说。**

核心理念：**写作即对话**——用户说话，智能体直接写。智能体的第一能力不是守规矩，而是**懂你**。

**能力哲学（S114 定稿，替代早期"按需开启/你要什么再装什么"）**：**默认可用、按需选用**——
像 Python：核心机制（语法/解释器）精炼硬编码，能力（标准库）默认齐全开箱即用，能力之间可组合增长
（加法的加法）。所有能力**默认注册**进智能体工具箱（Agent 知道有什么、随时可调，不注册=不存在），
**按需选用**（是否实际调用/是否注入上下文由 Agent 按任务判断，不默认全塞）。安全靠机制硬编码兜底
（沙箱/越界保护），**不靠隐藏能力**。

**战略定位：二次项目**——绿地独立建设，不复用旧代码，旧系统只作思想参考；**不做旧数据导入/转移**（主人 2026-08-02 决策 A，见 PROGRESS.md 决策记录）。版本号 v4.0.0 起步。

**升级方向**：功能升级 + 架构升级 + 美学升级（美学暂缓——未来换风格容易，关键在功能与交互）。

**北极星体验目标：摩擦前置且递减**
- 现状（坏）：用户下指令 → AI 闷头写 → 评审挑错 → 返工（摩擦峰值在最后）
- 目标（好）：种子交换 → 方向对齐 → 可观测写作（事前对齐，摩擦前置且递减）
- 所有设计取舍以此为准：好交互 = 早期花小成本对齐，后期零返工

## 1. 设计哲学（六条原则）

1. **易用** — 用户上手成本趋近于零。用户不需要先学会"卷/章/知识库/剧情链"等概念才能开始写作。
2. **简洁解耦去限制化** — 不过多用人类规则限制智能体发挥。参考 pi 设计哲学：核心极简、功能外置、默认强大、可观测。不内置权限弹窗/计划模式/待办清单/护栏——**默认可用、按需选用**（S114：能力全注册进工具箱，Agent 知道有什么；调用/注入按任务判断）。
3. **平滑性** — 从"只有灵感的人"到"有完整规划的作家"都能用好，能力随使用浮现，不设学习门槛。
4. **深度对齐** — 沟通成本不能大于写作成本——否则用智能体不如自己直接写。这是死线。
5. **极简方法论（双层）** — 机制层极简：最文本、最简单的方法优先；相信模型能力；自然语言承载；不过度工程（能一句话让模型做，就不写一百行规则）。能力层默认丰富：像 Python 标准库——默认齐全、开箱即用，不为"减负"砍能力（S114：写作领域 Python，不是汇编程序）。
6. **逐步展开（交流基础假设）** — 无论用户脑中信息多少，人类交流总是逐步、一句一句展开的，不会一次性给出全部。推论：
   - AI 不期待用户一次给全信息，也不在用户未展开时自行脑补（抢跑）
   - AI 的每次输出都是"下一轮对话的准备"——信息交换是小块、频繁、双向的
   - 用户展开密度本身就是信号：说得细=图景清晰（AI 多执行），说得模糊=还在酝酿（AI 多引导）
   - **能动性 = 跟随展开节奏**

### 硬编码边界（与"自然语言承载一切"并列，合为完整方法论）
> **机制硬编码（设计者写），内容自然语言（模型生成）。**

> **S114 补充："默认可用"是注册维度，不是注入维度**——能力默认注册进工具箱（Agent 知道
> 有什么），上下文注入仍按需（任务相关数据才进提示，不默认全塞）。机制硬编码保证：
> 能力"在架子上且随时能用"，而不是"藏起来"或"默认全塞"。

判断标准：
- 对"过程"的控制 → 硬编码（可靠性要求高：循环不能崩、数据不能丢、安全不能漏）
- 对"内容"的控制 → 自然语言/模型（创造力/判断力要求高）
- 行为安全边界 → 硬编码兜底（不能靠模型"自觉"）

**必须硬编码的三类**：
- **A. 过程控制**：Agent 循环（while-true/流式/重试/错误处理）、工具调用协议、上下文管道（消息结构/token 预算/压缩触发）、事件协议（SSE 类型/注册钩子）、并行调度（并发/超时/聚合）、安全底线（幻觉检测 fake_tool/fake_write、越界保护）、交互基础（SSE 传输/编辑器集成）
  - 重试为**可组合组件**（core.RetryingModel 包装，任何模型可套，不内嵌在具体适配器里）——换模型不丢流程基建（S15 落地）
- **B. 交互载体结构**（加速信息交换，设计者设计形状，模型只填充内容）：概念卡、方向卡、候选卡堆、结构树（大纲/卷章/图谱展示）、关键点图谱视图、氛围滑块组、能动性选择器、建议卡/提醒卡、说明书界面、场景拼图板
- **C. 数据存储结构**（保证可编辑）：条目元数据（来源/置信度/活跃度/锁定）、文档结构、图谱 schema

**模型八大局限的编码弥补**（硬编码"能力基础设施"）：
| 模型局限 | 硬编码组件 |
|---------|-----------|
| 记不住长篇小说事实 | 知识/记忆基础设施：图谱数据库（实体/关系/事件）、FTS 全文检索、项目档案、说明书 |
| 上下文窗口有限 | prune/summarize 两阶段压缩、写作前"当前时空点已知事实"检索注入 |
| 算不了数/算不准 | token 精确计算（tiktoken）、diff/patch、图计算（关系传播/路径）、统计聚合 |
| 不稳定（同输入不同输出） | 确定性校验：时间线冲突检测、设定冲突检测（图谱比对）、伏笔匹配（确定性部分）、章节结构校验 |
| 做不到的动作 | 工具执行：文件读写、文档解析（txt/docx/md）、多格式导出、网络搜索（**默认可用**：S114b 能力全注册不隐藏，写作 Agent 工具箱含 search_web/fetch_page，按需选用；S111-S112 对齐 pi-web-toolkit：Exa/Parallel MCP 无密钥带日期作者 → 360/Bing 降级，搜索+抓正文闭环） |
| 不会自己调度 | 流程基建：任务队列、并发控制、Supervisor、指数退避重试、超时熔断（core 提供可组合的 RetryingModel，任何模型可套） |
| 输出不结构化 | 解析管道：工具调用解析、JSON schema 校验、提取→入库数据管道 |
| 安全不可靠 | 安全底线：幻觉检测、内容安全过滤、成本/配额控制 |

**半硬编码（机制设计者定，内容模型生成）**：探索机制（并行结构/隔离/策略集机制硬编码，探索指令/方向卡内容模型生成）；检测网（三层结构/骨架默认值/报告格式硬编码，检测项/报告内容模型生成）；说明书（条目结构/分层继承/升级确认流程硬编码，偏好提炼/摘要模型生成）；能动性（自然语言行为描述机制/参数映射硬编码，档位描述模型+用户）；关键点图谱（存在机制/跨章注入逻辑硬编码，图谱内容模型生成）。

**完全交给模型/用户**：概念卡内容、方向卡内容、候选文本、检测项、偏好条目、摘要、写作正文、探索指令、用户自定义的一切。

## 2. 对大模型与写作本质的认识（理论地基）

- **大模型是"概率探索器"**：默认走最大概率路径 → 高概率区 = 平庸区（所有"像那么回事但没灵魂"的文本）。
- **优秀作品的"奇异点"在低概率高价值区**——默认采样永远走不到。
- **抽卡（Best-of-N）收益有限**：只能改善平庸区内的排序，到不了奇异区。
- **写作需要"航向系统"（探索指引），不是"护栏"（禁令/模板/扣分）**：
  - 死约束（禁令、模板、AI 味扫描扣分）→ 把模型钉在平庸区，应退役
  - 活约束（意图、情感目标、读者体验、张力方向）→ 剪枝搜索空间，让探索聚焦奇异区
- **写作起点是"种子"**：用户脑中已有新颖概念/激动场景 → 人机深度结合，非纯自主探索。智能体的任务是"把用户脑中的种子挖出来、确认、放大、实现"，不是"从零找到奇异点"。
- **种子 = 创作动力 ≠ 结构关键点**：用户可能只想写到"两人结婚"，但故事本身是冒险小说。种子是"必须到达的点"（情感动力），不一定是作品结构中心。作品由**关键点图谱**（冲突线/角色弧/伏笔/情绪峰值）支撑——关键点地位不亚于种子。
- **双向黑盒是摩擦根源**：
  - 人不知道 AI 倾向（换模型还会变）→ 解决：可观测的探索过程 + **AI 倾向档案**（AI 主动暴露当前倾向："我这个模型写对话偏克制"，让用户能预测它、敢放手）
  - AI 不知道人的种子 → 解决：种子捕获（概念卡 + 关键歧义点提问）
- **大模型本身是"不稳定的库"**：训练数据内化了海量类型学知识（废柴流/升级流/双线/悬疑揭示/三幕/英雄之旅…）——不需要从零外部建库，但每次生成会漂移（见机制 6 稳定性处理）。

## 4. 架构（多包 + 技术选型）

### 技术选型（标准：AI 擅长写 / 用户方便部署 / 方便升级打包）
- 后端：**Python 3.11+ / FastAPI / SQLite**（嵌入式，用户零安装数据库）
- Python 包管理：**uv workspace**（monorepo 多包，锁文件清晰）
- 前端：**React 19 / TypeScript / Vite / Tailwind 4 / TipTap（编辑器）/ Zustand（轻量状态）/ npm（单应用）**
- 桌面壳：**轻量自研**（Python WebView）+ PyInstaller 打包（不引入 Electron/Tauri 重型依赖）
- 部署：源码一条命令（`uv run` + `npm build`）；用户=桌面壳包双击即用
- **升级方便的关键**：数据在用户目录（data/），版本升级=替换程序，数据不丢

### 仓库结构（单仓 monorepo）
```
anyspark/
├── pyproject.toml        # uv workspace 根
├── packages/
│   ├── core/             anyspark-core     内核包（不依赖任何包，单向依赖）
│   ├── explore/          anyspark-explore  探索包
│   ├── align/            anyspark-align    对齐包
│   ├── template/         anyspark-template 模式库包
│   └── desktop/          anyspark-desktop  桌面包
├── frontend/             # React 创作台（npm 单应用）

├── tests/
└── scripts/
```

### 包划分与依赖
- **anyspark-core**：Agent 循环、极简工具集、存储接口。不依赖任何包（单向依赖，无循环）。
- **anyspark-explore**：意图理解 / 探索策略集 / 多智能体探索者 / 定向再探索。依赖 core。
- **anyspark-align**：说明书（分层）/ 提炼器 / 摘要器 / 注入器 / 信号采集。依赖 core。
- **anyspark-template**：三层模式库（模型内存/默认库/外部库接口）。依赖 core（可选）。
- **anyspark-ui**：前端创作台（稿纸/卡片/滑块/抽屉）。依赖后端 API。
- **anyspark-desktop**：桌面壳与生命周期。依赖后端。

### 协议层（core 内聚，必须极小）
- 循环（while-true）：读系统提示 → 执行工具 → 回填结果 → 输出
- 工具调用协议：模型怎么调工具、参数解析、结果回填
- 上下文管道：消息结构、系统提示组装、token 预算
- 事件协议：核心只发通用事件（text/done/error/tool_call）+ 类型化数据负载；包通过**注册钩子**扩展自定义事件类型
- 存储接口：会话/消息最小持久化接口（实现可换）

### 核心原则
- 功能层全部可解耦（AI 时代功能 = prompt + 工具 + 数据处理，全可外置；核心不"知道"功能存在）
- 能动性 = 提示注入（align 包写，core 只读）；判别 = 工具结果返回；事件 = 注册钩子
- **能力默认可用（S114 定稿，替代 S15"默认关"）**：组合根（app/server）把全部能力注册进工具表（Agent 知道完整工具箱，不注册=不存在）；`enable_*` 语义翻转——默认全开（可用），显式传 False 可禁用（省工具表 token/安全隔离极端场景）；`extract_graph`（图谱抽取可关省 token）、`skip_inject`（跳过 manual/graph/agency/bias/mood 任意子集）不变（注入维度）。实测 45 工具全注册 ≈ 3.7K token 常驻，1M 上下文下可忽略。
- **YAGNI 更新（S114）**：不建一次性死接口——能力默认齐备 + 组合增长（加法的加法：搜索+抓取+图谱+工作流互相咬合成新能力），不为"还没用到"砍能力。
- 商业化分层：~~免费 core + 付费增强包~~ → **S114c 主人拍板：已实现增强包不考虑商业化，满血内置**；商业化只留“外部数据服务”含义（如外部扩展库/平台库，见机制 6，未实现）

## 5. 十大核心机制（完整规格）

### 机制 1：探索-判别双循环（写作机制）
```
用户一句话（意图）→ 航向解析（奇异点坐标大致在哪）
  → 多路探索（N 个差异化候选：换叙事策略/切入点/结构/文风偏移）
  → 判别（哪个最接近航向：LLM 判别器 + 人类在环选择）
  → 迭代收敛（选中方向 → 探索细节 → 再判别 → 收敛）
```
- **用户不是指挥者，是判别器**（选择比描述容易）
- 每次选择同时写进用户模型（对齐）

### 机制 2：能动性协议（AI 做多少）
- 五级协议（默认档位，自然语言描述，用户可加可改）：
  - 0 只听写：严格按用户原文/原意输出，不添加不改动
  - 1 执行+填肉：按用户骨架填充，不改变结构
  - 2 补全标注：补全细节，但标注哪些是我加的
  - 3 建议扩展：提出新方向供用户选
  - 4 自主发挥：自行探索写作，用户验收
- AI 每轮可声明级别，用户一键点选修正；反馈自动调节（删=降级，接受=升级）
- 长期：能动性是**心智模型的输出**而非独立旋钮——合作久了 AI 自然知道要什么程度，显式声明退场（只在冷启动/高不确定时出现）
- 隐式信号：修改频率、接受率、沉默、删改内容
- 模型参数映射（可调默认）：档位低 → 温度低、思考强度高（精确执行）；档位高 → 温度略高（探索交给多路，不靠单次发热）

### 机制 3：对齐系统（替代记忆系统）
- **路线选择：对齐优于记忆**。记忆路线有本质困难（存储-检索完备性无法达到）；对齐追求"方向正确"而非"完整记录"，可持续逼近，有容错性（错了纠正即新信号）。一条偏好陈述可指导几百次写作；百条历史记录每条只对特定时刻有用 → 信息密度决定对齐更优。
- **用户模型 = 可解释偏好档案**（自然语言短句 + 来源 + 置信度 + 活跃度），模型无关（新模型可读，换模型不丢）
- **对齐信号全部来自操作**（选择/修改/删除/反馈），零打字成本，无表单
- **AI 的提问 = 不确定性信号**：只在不知道该做什么时才问，且问的是**关键歧义点**（"主角此时是恐惧还是渴望？"）而非泛泛问卷
- **提问频率 = 对齐进展的可视化**：AI 越问越少 = 默契度增长的可见证据
- 完整集成规格见第 6 节（T3）

### 机制 4：低摩擦交互层（操作式表达）
- 打字 < 说话 < 脑内思考 → 把"描述"变"操作"
- 交互通道分层（认知成本）：点选(0.3s) → 滑块/旋钮(1s) → 拖拽(2s) → 画布操作(3s) → 打字(最后手段)
- 组件：能动性选择器、方向诠释卡、氛围滑块组（align.mood 提供注入块，S15 归属对齐包）、场景拼图板、候选卡堆、改写渐变条
- **每个操作 = 结构化对齐信号**（操作即语义——打字需要解析语义，操作本身就是语义）
- **共同对象原则**：双方在同一对象上交流（概念卡/结构图/候选卡），卡片是"共享的稿纸"

### 机制 5：前端空间设计（创作台，美学暂缓）
- 核心：把"并列的控制台"变成"**有主角的创作台**"——稿纸为主角，功能全保留
- 三层空间：
  - 第一层：稿纸（视觉主体，TipTap 编辑器）
  - 第二层：写作上下文（候选卡/氛围滑块/能动性圆点，轻量浮现）
  - 第三层：设定工具抽屉（知识/角色/时间线/地图等，按需呼出，保留 Ctrl+数字快捷键）
- 对话从聊天窗口降为纸边批注；视觉收敛（荧光色→1 主色 + 3 语义色；字号层级重建；质感动效）
- 旧工程资产参考（只借鉴思想，不复用代码）：19 面板分组导航、分屏、命令面板、快捷键、焦点模式

### 机制 6：结构模式模板（三层体系）
- **核心认知**：大模型本身就是“不稳定的库”——内化了海量类型学知识，不需要从零外部建库
- **三层体系**（S124 命名消歧：模板库 L1/L2/L3 改描述性命名，避免与档位 L2/L3 打架——
  档位的 L2=AI 建议档位/L3=自然语言生成档位见 §12.23，两者无关）：
  - **模型内化层**（原 L1）：免费、即时，解决“有没有”
  - **精选默认库**（原 L2 开发者默认库）：精选少量高质量模式，解决个人用户大部分问题（内容工作是编辑能力非编程）
  - **外部扩展库**（原 L3 进阶外部库）：用户导入/平台库/社区共享——商业化方向（B 端平台是深水区；C 端内化+精选够用）
- **统合方法：自然语言是唯一介质**——三层模式都以自然语言描述存在（+ 轻量元数据），模型自己读、自己融合、自己组合。**不建组合引擎/匹配规则/冲突检测**（都是强制护栏）
- **模板四要素元数据**：{ 粒度(全书/卷/章/场景/段落), 位置(开局/发展/高潮/结局), 功能(铺垫/主线/悬念/爽点/情感), 可变参数 }
- **边界（锁死）**：模板只做"探索方向的生成器"（粗粒度航向），绝不做"内容的框架"（填空=套路文，且模板被大量使用后自身变成新平庸区）。模板是起点，变体才是目标
- **稳定性**：模型内化知识每次生成会漂移 → 用户确认过的方向固化为自然语言记录（进项目档案/用户模型），可复现可引用；固化时机=用户确认，模板机制与对齐机制在此合一
- **提取能力边界**：LLM 能做"鉴定"（套人类已命名类型学框架——网文社区命名是公共知识），做不了"发明"（发现未命名的新奇异结构）；人类提供分类学，LLM 做标本鉴定
- **交互红利：流派术语=共同语言**——候选卡直接用术语标注（"废柴流开局·反差铺垫"），懂网文的作者秒懂
- **探索方向三来源混合场（模板不独占）**：
  - ① 模板派生：从三层模板体系生成（服务小白）
  - ② 作品内在生长：完全从种子+已有内容自然推导，不走模板（服务原创性；纯靠模型对作品的理解，不依赖库）
  - ③ 用户指导：用户脑中非常规约束直接作为航向（"没有情节只有氛围"）（服务专家）
  - 候选卡永远混合三来源（例：4 张卡 = 2 模板 + 1 自由生长 + 1 用户直觉）；用户选模板还是选自由卡 → 对齐信号 → 未来混合比例自动调整（模板占比 = 用户模型的输出）
  - 一句话：**模板是探索的脚手架之一，不是道路本身；道路由三来源共同铺成**

### 机制 7：多智能体探索（探索-判别的实现形态）
- **动机**：同上下文多选项存在**伪多样性**（一个模型给 4 个选项会被自己第一个思路锚定、向中间收敛）；上下文隔离 → 真多样性（multi-prompt sampling / ensemble）
- **流程**：
  ```
  [意图理解者] 理解种子+用户要求 → 对齐确认（先给用户看，摩擦前置最便宜的纠错点）
        ↓ 确认后
  [探索策略集] 主 Agent 定义差异化分派（按叙事维度/模板/自由/用户指导分派）
        ↓ 并行（asyncio.gather，轻量上下文）
  [探索者 ×3-4] 各自产出方向卡（带术语标注）
        ↓
  [用户判别] 选/杂交 → 反馈信号 → 定向再探索（多轮）
        ↓
  [固化] 选中方向落盘进项目档案
  ```
- **默认探索维度**（自然语言描述，用户可增删）：情节驱动 / 角色驱动 / 氛围驱动 / 结构实验 / 文笔质感 / 用户指导
- **8 项约束**：
  1. 成本控制：探索者用轻量上下文（种子+关键设定摘要+方向指令，不带全量图谱）；并行调用时间≈单次；探索层可跑 Flash，Pro 留给写作
  2. 轻量优先：探索者多数是单次 LLM 调用，不需要完整 while-true 循环+工具；只有需查资料的探索者才给工具；写作 Agent 默认带完整工具箱（S114：搜索/抓取/考据/评审/图谱/工作流全注册，Agent 按需选用——不注册=智能体不知道有这能力=等于没有）
  3. 多样性不自动保证：主 Agent 先定义探索策略集，每个探索者拿不同维度指令
  4. 意图理解者产出"对齐确认"而非方向——两阶段：意图确认 → 方向探索
  5. 多轮循环：单轮 4 卡可能都不对，用户要的是杂交（"A 设定+B 结构"）→ 定向再探索
  6. 选中方向固化进项目档案（探索者隔离，主 Agent 需要记住方向细节）
  7. 轻量上下文必须含"已固化设定约束"（一句级：女主=医者）——探索自由但不得撞已固化的墙
  8. 展示顺序效应：多卡随机排序/分组，避免位置偏见污染对齐信号

### 机制 8：用户自定义规则（用户边界 + 两级实现）
- **区分：用户自定义边界 ≠ 系统护栏**
  - 系统强加规则（AI 味扫描扣分）= 护栏 → 删
  - 用户自己要的规则（"我不要破折号"）= 用户主权 → 必须支持
  - 去限制化去的是"系统的限制"，不是"用户的限制"
- **动机：用户需求加不完** → 靠"让系统自己能扩展"解决，而非预定义所有规则
- **两级实现**：
  - ① 轻量规则编译器（默认，极小）：用户自然语言规则 → 内置编码 agent 生成检测函数（正则/简单逻辑）→ 注册进检测网用户自定义层。只读纯文本处理，无文件系统访问，安全风险极低
  - ② 编码扩展包 anyspark-codex（内置默认可用，S114：安全靠沙箱兜底不靠隐藏；run_code 描述已写明"不可读写文件/访问网络"，显式可禁）：复杂自定义工具/分析时启用，可打包 pi 类编码 agent，沙箱执行
- **用户自定义检测项三种来源**：选项卡点选 / 自然语言描述（→轻量编译器）/ 复杂规则（→编码扩展包）
- 完整 pi 嵌入评估：跨语言集成成本高（Node/Python）+ 能力大部分用不上 → 降级为可选扩展包

### 机制 9：检测网（三层协作生成，替代死护栏）
- **为什么以往检测网失败**：静态规则只能覆盖已预见的错；误伤（分不清合法创作与错误）；平庸标准（合规≠写好）
- **三层协作生成**：
  - ① 系统骨架（第一性原理，硬编码默认值，用户可增删）：一致性（事实/设定/时间线） / 动机因果 / 情感连贯 / 信息流（悬念揭示节奏） / 结构节奏 / 预期管理（吊起的期待兑现） / 主题连贯（母题不漂移）
  - ② AI 动态生成：模型针对当前作品+阶段具体化检测项（"第 3 章自称孤儿第 7 章有母亲——矛盾"），检测项=自然语言、随作品演化
  - ③ 用户自定义：用户毒点/关注点（机制 8 实现）
- **多检测者并行**（复用多智能体）：一个查一致性/一个查情感弧/一个查信息流……轻量，汇总成审读报告
- **建议而非门禁**：结果是报告+建议，不做"不达标暂停"；**硬伤（设定矛盾/断章失忆）才标红提醒**
- **定位：编辑的第二双眼睛**（帮用户发现盲点），不是审查者；决定权在用户
- 与 AI 味扫描的本质区别：帮把故事写好（第一性原理） vs 别像 AI 写（合规）
- 检测时机（倾向，实施时定）：章末轻量 + 用户喊深度，不打断写作
- 确定性部分（时间线冲突/设定冲突/伏笔匹配）由代码硬编码校验（见第 1 节"模型局限弥补"）

### 机制 10：资料消化（补全资料库能力）
- **流程**：
  ```
  用户上传材料 → [入库消化·自动] 模型生成材料摘要卡（主题/要点/关键设定/涉及角色/术语）
    → 摘要卡自动关联图谱实体（角色/地点/事件）→ 材料原文保留（可查全文）
  写作/探索时 → [按需检索]（FTS/图谱关联/模型判断）→ 注入摘要卡（省 token）
    → 模型需细节再查全文 → 引用处标注来源（防串书）
  ```
- **摘要卡是核心**：入库时模型压缩成摘要卡，写作注入摘要卡而非原文；信息密度高省 token
- **图谱关联**：摘要卡提到的人物/地点自动链接知识图谱 → 写作时"检索当前时空点已知事实"自然带上相关材料，图谱=统一关联枢纽
- **用途标注**（衔接参考书用途隔离）：文风参考 / 设定事实 / 两者——防材料角色串进正文
- **来源标注**：正文引用材料可追溯
- 分工：资料=私有素材（作品世界/参考）；模式库=结构模板（故事组织）；说明书=用户偏好（怎么写）——三者并列不重复

## 6. T3：对齐系统与 Agent 循环的集成（完整规格）

### 双轨提炼（每次会话结束时自动运行）
- **摘要器**：对话 → 场景记忆（发生了什么/进行到哪/做过哪些决定）→ 项目档案（承担延续性）
- **提炼器**：对话+操作 → 偏好条目（用户倾向什么/什么有效/什么雷区）→ 用户模型（承担对齐）
- 下轮会话开头：AI 主动展示 1-2 条"我从上次学到的" → 用户确认/纠正/丢弃（确认升置信度，纠正即修正）

### 说明书形态（对齐的载体）
- 本质：**可读性高的自然语言文档**（像说明书，多条目），系统自动维护，用户是最终编辑者
- 跨模型：纯自然语言，任何模型可读，文档开头带"使用说明"
- **条目元数据**：来源（自动提炼/用户手写）+ 置信度 + 活跃度 + 锁定状态
- **用户编辑权**：直接改文字 / 删除 / 新增 / **锁定**（锁定条目系统永不自动改）
- 解决：摘要污染（来源标注）、用户不知系统如何看自己（可读）、提炼错误（可改）、无法操作（条目化）、用户主权（锁定）

### 说明书分层（项目级主体 + 全局级极小化）
- ① **项目说明书**（每本书，主体）：关键点图谱/设定约束/方向固化/进展/书内偏好（用户大多数偏好是项目内的，不串书）
- ② **全局说明书**（极小化）：硬习惯/雷区/沟通方式——仅用户确认的跨书稳定条目
- ③ 会话层（临时，不落盘）
- **继承**：注入优先级 项目级 > 全局级；项目级永远可覆盖全局
- **跨层升级需用户确认（防跨书污染）**：系统发现多本书重复偏好 → 建议升级全局（"三本书都删血腥，设为全局雷区？"）→ 用户确认才进全局，锁定 🔒
- 校准仪式：用户偶尔审查说明书 = 对齐校准（看到错的就改）；审查可作低频可选功能

### 对齐闭环（三层）
自动提炼（建议）→ 说明书载体（可读可改）→ 锁定机制（用户主权）

## 7. T2：种子→作品完整交互蓝图（交互规格）

> 原则贯穿：摩擦前置（每步先对齐再前进）、操作即表达（打字最后手段）、按需深入（用户到哪层探索到哪层）、展开密度即信号（输入越完整，低级探索越自动跳过）
> **核心循环只有三个对象：概念卡（理解）→ 方向卡（选择）→ 稿纸（产出）**，其余都是变形

### 阶段 0 · 进入（几秒）
- 唯一入口："这本书你想写什么？"——一句话 / 粘贴完整大纲（自动消化，不强制分卷建章）
- 平滑性：入口只有一个，能力随输入密度自动分级
- **专家路径**：输入密度高（粘贴完整骨架）→ 自动跳过低级探索，直接进图谱/写作

### 阶段 1 · 种子捕获（第一次对齐，1-2 分钟）
- 用户自由说种子（画面/概念/情绪/设定都行）
- AI 不立即干活：① 复述成**概念卡**（画面核心/情绪基调/类型直觉/种子位置(开篇?/高潮?/结局?)，可点选修正）② 只问 2-3 个**关键歧义点**（AI 提问=不确定性信号，只问影响方向的问题）
- 概念卡=共同对象；种子位置确认（创作动力≠结构支点）；能动性默认 0-1 级

### 阶段 2 · 方向探索（几分钟）
- 多智能体并行（意图理解者→探索策略集→探索者×3-4 轻量），产出**混合三来源**方向卡（2 模板+1 自由生长+1 用户直觉，带术语标注）
- 用户判别：选它 / 感兴趣展开（定向再探索多轮）/ 再来一批；**"我已有想法直接写"出口**
- 选中方向→结构化摘要**固化进项目档案**（含已固化设定约束，后续探索不得撞墙）
- 对齐信号：选模板 vs 自由卡 → 学习用户类型 → 未来混合比例自动调整

### 阶段 3 · 关键点图谱（作品级规划，可选深入）
- AI 基于概念卡+方向生成图谱草案（主线冲突/角色弧/情感核/世界规则/情绪峰值/伏笔/节奏——网状非大纲）
- 用户操作：增/删/改/标"我在意/不需要"——操作即对齐信号，关注点跟随在此学到
- **图谱=跨章长期记忆**：每章写作时注入其当前状态（哪些推进/哪些没收），从规划工具升级为活的长期记忆；可演化非一次性工程
- 不强制：小白可跳过直接写作，专家可深耕；分层探索（作品级→章级→场景级，用户说到哪层探索到哪层）

#### 伏笔管理（S31 补充：A/B 分级 + 老龄化 + 场景化回收）
**定位（哲学红线）**：伏笔管理是**镜子非警察**——系统提供信息（开放了什么、开了多久），判断永远是作者/内容的事。**绝不输出回收率**（没有完美回收的作品，伏笔管理烂不影响作品伟大性——回收率不是质量评分）；**分级靠作者声明**（系统不裁决"这算不算重要伏笔"，只尊重作者承诺）。
- **A 类剧情钩子（priority=must，必须回收）**：作者/AI 主动声明的**主线承诺**（对读者的契约，如魂器、斯内普真相）——注入时**明确列出（★）**、一章收尾检查、不回收=违约风险
- **B 类细节线索（priority=soft，可回收可不回收）**：写作中自然捕捉/生成的铺垫细节——**旁观不打扰**（只汇总数量），回收是加分不回收无损
- **老龄化**：登记时记录章节序号（planted_order），注入/收尾标注"已开放 N 章"——**中性事实，不设阈值不评判**（开放久可能是故意留到结局）；治"冰与火式铺陈失控"的认知负担（系统记住，作者不用记）
- **生命周期诚实可见**：登记时刻+回收时刻完整轨迹——"找补"（海贼王式事后追认）是作者合法自由，系统不禁止不评判，只让开放时长可追溯（作者自我觉察）
- **场景化回收语义**：
  - 完整书导入：提取后**全部 resolved + 归档章**（书已写完，伏笔都已揭开——提取=归档验证，非追踪）
  - 不完整书（如只导入第一部）：open 保留 + 续写注入 + 老龄化提示
  - 自写书：**主动登记**（一句话"记一下"）→ 落盘**自动回收**（PlotResolver 识别揭开）→ 一章收尾钩子检查（提醒非门禁）
- 登记入口：主动声明（作者/AI）+ 按需生成（PlotGenerator 对已有文本提取）；不做常驻自动捕捉（成本+噪声，影子层保持轻量）
- 防烂尾机制：只对 must 钩子做承诺追踪（注入 ★ 列出 + 收尾检查）——铺陈自由不被限制，承诺不被遗忘

### 阶段 4 · 按需深入
- "我想写第一章"→只探索第一章；"理下第 3-5 章"→卷级；"直接写"→进稿纸。**不为未写的部分付探索成本**

### 阶段 5 · 写作（主体，稿纸为中心）
- 用户在写：AI 后台工作（记住设定/一致性检查，不打扰）
- "你写这段"：声明级 3-4 → **方向声明**（"我准备写：主角推开玻璃…"）→ 用户 0.5s 确认/调级 → 探索-判别生成 → 候选卡 → 选
- **方向声明限定**：只在方向不确定/能动级别变化时出现，确认后连续写作不再重复确认（默许=授权）
- 卡壳：建议卡（可拖入稿纸或丢弃，从不直接改稿）；选中段落要改：候选改写卡堆+渐变条（保原味↔大幅改）
- 连贯性后台化：知识库/设定约束 AI 自动维护；撞已固化设定→温和提醒卡（非弹窗打断）

### 阶段 6 · 一章完成（轻量收尾）
- 自动：更新关键点图谱（哪些推进了）+ 一致性摘要卡（一句话非强制）+ 下一章衔接提示（"建议推进角色弧，展开吗？"）
- 自动评审可用（S114 哲学 + S64 落地）：评审工具无条件注册，用户喊"帮我看看这章"Agent 即自主召集评审——"默认关的工具=没人用的残废通道"（S63 教训）；是否评审仍由用户触发（按需选用）

### 贯穿：对齐积累
- 每次点选/修改/删除/标注/调级→对齐信号→用户模型更新→注入后续全部探索与写作；信号带置信度（单次操作不产生强结论）；提问频率递减=默契度增长的可视化

## 8. 数据设计（形态规格）

### 数据分层（全部自然语言承载，模型无关）
1. **项目说明书**（每本书）：关键点图谱 / 设定约束 / 方向固化 / 当前进展 / 书内偏好——自然语言文档，条目化
2. **全局说明书**（用户级，极小化）：硬习惯 / 雷区 / 沟通方式——仅用户确认的跨书稳定条目
3. **知识图谱**（SQLite）：实体（角色/地点/事件）/ 关系 / 时间线——AI 事实源，写作时"当前时空点已知事实"检索注入
4. **资料库**：材料原文 + 摘要卡（主题/要点/设定/角色）+ 图谱关联 + 用途标注
5. **模式库**：三层（模型内存/默认库/外部库），自然语言描述 + 四要素元数据
6. **会话/章节**：消息（结构化 Part）+ 章节内容（版本历史）
7. **全文检索**（FTS）：派生索引，可重建

### 条目元数据（说明书/偏好条目通用）
- 内容（自然语言短句）
- 来源（自动提炼 / 用户手写）
- 置信度（0-1）
- 活跃度（高/中/低，随使用衰减）
- 锁定状态（锁定条目系统永不自动改）

## 12. 设计演进补记（S32-S46：实测驱动的设计变更）

### 12.1 智能体能力闭环（S32）
- **探索工具化**：`explore_direction` 无条件注册为写作 Agent 工具（方向模糊→多智能体探索→方向卡呈现用户选择），补机制 7 的 Agent 侧闭环（此前探索仅 HTTP API 人驱动）
- **查资料默认可用**：`read_material` 归 `enable_domain` 默认注册（S108）；`check_text` 已退役（S63，被 review_chapter 取代）——S114 哲学：能力不隐藏

### 12.2 档位记录集（S35，机制 2 升级）
- 档位从"固定五级枚举"→**全局档位记录集**（可增删改/恢复默认/温度入档）
- 默认五级为稳定基线；`agency_state` 只存当前档位 id
- **职责边界（S35b 修正）**：档位只管**能动性**（主动程度）；文风/喜好/毒点是**心智模型**的职责（独立系统、包罗万象、渐进式披露，后续设计）——两者正交
- **S61 补齐**：L2（AI 看心智建议档位 `POST /api/mind/agency-suggest`，LLM 语义判断，启发式降级对照）与 L3（自然语言生成档位 `POST /api/agency/generate`，候选+人工确认闸门）已实现（详见 §12.23）

### 12.3 写作技巧内容化（S43，参考 pi skills）
- **写作技巧从 DEFAULT_SYSTEM 抽出**为 skill 式内容载体（name/description/content/enabled，可增删改/开关）——默认种子：粒度感知/角色认知边界/氛围克制
- DEFAULT_SYSTEM 回归极简（~230 字，只留行为底线）
- 渐进式披露：索引（描述常驻）+ 内容（正文注入）；技巧多了后只留索引、正文按需

### 12.4 知识层分层（S37/S41/S42）

### 12.9 运行时模型配置与思考强度（S47）
- **背景**：此前模型固定 DeepSeek（`.env` 启动时静态配置），无运行时切换、无思考强度选择
- **模型注册表**（`anyspark.models.registry`）：SQLite 持久化多模型配置（供应商端点/模型名/api_key/窗口/温度/思考强度），空库从 `.env` 播种默认——升级即用、旧行为不变；CRUD + 激活切换（`GET/POST /api/models`、`DELETE /api/models/{id}`、`POST /api/models/{id}/activate`）
- **ModelProvider**：实现 core Model 协议，委托给**当前激活配置**——切换后所有持有它的组件（Agent/图谱抽取/检测/探索/后台任务）即时跟随，无需重启、无需改组件（组件只认识 Model 协议）
- **请求级覆盖**：ChatRequest 加 `model_id`（指定模型，缺省用激活）+ `thinking`（思考强度覆盖）——显式指定 > 当前激活
- **思考强度**：DeepSeek v4 系列默认开思考；`reasoning_effort`（OpenAI 标准参数，顶层直传，low/medium/high/xhigh/max）控制强度；`off` 用 `extra_body={"enable_thinking": False}` 显式关闭（非标准参数）。思考内容经 `reasoning_content` 返回（当前不展示，仅用于生成）
- **哲学保持**：配置内容（供应商/模型名/强度）是自然语言数据可增删改；机制（表结构/激活语义/委托/缓存）硬编码；说明书/图谱等载体"模型无关，换模型不丢"继续成立；重试/压缩等流程基建不依赖具体模型（S15 组合式）
- **已知限制**：token 预算窗口在启动时按当时激活模型计算，切到窗口不同的模型后重启才更新预算（activate 时打日志提示）；~~换非 DeepSeek 兼容供应商需新适配器（YAGNI 不预建）~~（S131 已加 anthropic/gemini/responses 三协议，见 §12.44；Bedrock/Vertex 原生 SDK 仍 YAGNI 不预建）

### 12.10 工作区化（S48，主人拍板：小说特化版 pi 第一步）
- **定位**：形态变革起点——从"应用系统"（后端 API + React UI）走向"特化 agent"（对话驱动、文件自由），保留后端完全可用
- **每项目一路径**（极简版 B，无过度设计）：
  ```
  书架/<项目>/
  ├── 上传/          # 原始存档：任何格式，只读不碰（上传物原地，不复制不转换）
  ├── 章节/          # md 正文（权威）：001-第一章-雨夜.md（文件名承载序号，正文纯文字）
  ├── 卡片/          # 可读产物：角色卡-陈渡.md、场景卡-雾城.md
  └── anyspark.db    # 状态库（全局单库，book_id=项目名）：图谱/伏笔/计划/版本历史
  ```
- **章节双写**：`write_chapter`/`patch_chapter` 写 md 文件（权威）+ SQLite chapters 表（镜像，供图谱抽取/检测/伏笔回收等既有管线零改动读取）；`/api/workspace/import` 单向同步"文件 → 库镜像"（人工直接编辑 md 后调用，内容变化才写版本历史）
- **上传**：`/api/upload`（base64 JSON，零新依赖）→ 上传区存档
- **读路径零改动**：list/read 章节读库镜像；图谱抽取/检测/伏笔回收/影响分析全读库——双写保证一致性
- **Token/效率**：注入（token 大头）只依赖状态库与存储无关；md 化买的是 agent 文件本能（模型对文件系统的理解是训练固有）+ 人工可直接打开编辑 + git 友好

### 12.18 心智模型横断决策（S51，主人讨论定稿）

> 主题：心智模型的**更新方式全景 + 存储介质 + 长会话更新策略**。此前心智模型只在 12.2(S35b)、12.17(S50) 定义为"会话规划器、非注入块"，本节补齐它的运作全貌。

#### 定位重申（承接 S50）
- 心智 = **会话规划器**：按用户/项目/会话分层，主循环接请求时据此决定协作策略（主动度/确认度/追问频率/格式偏好/该不该问）——不是注入块、不直接注给写作工具。
- 心智内容多是"习惯/文风/喜好/雷区/边界"，输入数据多；输出形状恒定（一个策略决策）。

#### 更新方式全景（7 种）
| # | 方式 | 触发 | 置信度性质 | 状态 |
|---|------|------|-----------|------|
| 1 | 用户主动"记一下" | 显式 | 高（用户亲口）| 🟡 需新增（偏好侧登记入口；参照 plot_register 形态）|
| 2 | 归档后模型分析更新 | 轮末/会话闭幕 | 中（自动提炼）| 🟠 已有雏形；长会话升级为多步聚焦 |
| 3 | 用户查看/手动编辑 | 低频审查 | 高（用户手写）| ✅ 已有（说明书编辑/锁定）|
| 4 | 下轮开头 AI 展示学到 | 会话开 | 中对冲 | ✅ 已有 |
| 5 | 实时负例捕获（否定→雷区）| 即时 | 中低 | 🔴 新，优先补 |
| 6 | 跨会话对账纠偏 | 周期 | 校正作用 | 🔵 后补 |
| 7 | 会话内弱信号快照 | 过程 | 低（供轮末参考）| 🔵 新，长会话地基 |

- 1 与 5 互为镜像：1=显式"记一下"，5=隐式否定/撤回即时标记低置信度雷区——防隐式信号被上下文稀释丢失。
- 2 应拆两层：**过程稀疏记录(7) + 归档时多步聚焦归并(2)**，合起来才是超长会话正确形态。

#### 长会话更新策略（50 万 token 一轮的现实）
- **现实**：一轮对话可达 50 万 token（主人实测），远超"一次性通读总结"的可行区（长上下文+RAG 在百万级仍会失效，见 BEAM/ICLR2026 共识）。
- **错误形态**：轮末拿 50 万 token 对话+思维链全量重读、现找偏好 → 注意力稀释漏关键 + token 爆炸。
- **正确形态**：**进行时稀疏记录（发生时按主题归位，靠 recorder 思维链 + signal_collector 操作信号）→ 归档时按主题簇多步聚焦归并**（先索引定位主题 → 聚焦代表段深读 → 归并成条目）。本项目的"关联结构"用主题簇/项目档案/偏好条目（带元数据）承载，**不需要 Cue–Tag–Content 图**。
- **触发阈值**：仅超长会话（如 >100K token）启用多步聚焦；短会话仍走一次性提炼（YAGNI，不过度设计）。

#### 存储介质决策：自然语言（明确不用向量）
- **定论**：心智模型以**自然语言记录**（一行自然语言 + 元数据外壳：来源/置信度/活跃度/锁定，DESIGN §8），**不用向量/embedding 库**。
- **为什么不用向量**：
  1. 模型无关硬原则（换模型不丢）——向量绑定模型需重嵌，违约。
  2. 人机双读 + 用户手动编辑/锁定——向量不可读不可改，违背用户主权。
  3. 心智是小规模、有结构、需人改的载体，不是海量非结构化文档——向量是后者的场景。
- **心智的检索不用向量**：SQLite FTS5 全文检索 + 元数据过滤 + 大模型读自然语言做语义挑选已全覆盖。向量只在"海量非结构化语义召回"才值，心智不是该场景。
- **自然语言的三个下滑面的解法**：
  - 膨胀重复/矛盾 → 元数据驱动收敛（活跃度衰减沉没冷条 + 置信度 + 锁定）——机制保管理，自然语言保可读，两者配合。
  - 无粒度 → 固定最小结构（一行自然语言 + 元数据 + 可选出处），机制硬编码外壳、内容自然语言。
  - 字面搜索有限 → 未来超大规模再议，YAGNI 当前不做。

#### 心智与记忆的边界（防错位，承接 §机制3）
- 心智承载"怎么写/怎么协作"（偏好/习惯/策略）→ 自然语言条目。
- 记忆承载"已发生的事实"（图谱/项目档案/设定档）→ 各自的结构化存储。
- 两者不做向量化是共识；心智更不需要向量（事实记忆的图谱检索也只用 FTS/图算子，无向量）。

### 12.18b 叙事技巧生成器（S54：文风提炼 → skill 候选）
- **场景**：作者喜欢某小说文风 → 导入原文 → 提炼可执行 skill（五段式）

### 12.43 拆书三层模型（S114：实测驱动——猎手准则 367 万字验证）

**背景（主人讨论）**：S106 拆书（16 段字符均匀抽样+归并）对文风够用，但抓不到
全书级叙事机关——主人用《猎手准则》（367 万字/1281 章）验证：均匀抽样 5% 覆盖 +
字符窗口切碎章节边界，两份 skill 都未发现"时间回环"结构（主角穿越回过去发现经历
受过去的自己安排）与主角最终目的（重启世界/抹除过去/缔造新世界）。

**结论（实测证据）**：
- 抽样+局部提炼+归并结构上抓不到跨全书的全局关系（回环需"把第30章与第700章连起来看"）
- 骨架扫描（仅卷+章标题轨迹，无正文）能发现全局机关——猎手准则标题含
  《坏档》《重开》《第零战院和时间机器》《过去，未来，造物主》，模型据标题轨迹
  推断"时间循环/世界重置"机制 + 主角最终目的，两次实测稳定

**三层拆书定案（generate_book）**：
- ① **微观方法论**：结构感知选章（按卷分层首/25%/75%/尾+全书首尾，整章拼批）→
  分批拆解（GENERATE_PROMPT_BOOK 7 维）→ MERGE 归并成一份「书名」skill（target=both）
  ——抽样单位从字符窗口变整章（章节边界完整、章末钩子可见）；无章结构回退 S106 字符均匀
- ② **骨架扫描**：卷+章标题（无正文）→ 结构笔记（跨卷机关/主角目的/阶段，引用章号）
  ——唯一能看见全书关系的视角；1 次调用成本极低
- ③ **定点精读**：笔记机关关键词定位原文直接揭示段（如"回到过去""世界重启"）+ 机关章
  + 首尾章 → 精读提炼架构技法 skill（type=main，如「坏档与重开：时间循环式叙事」）
  ——骨架笔记仅作线索需原文验证（防"先给答案→编造"）；example 机器校验
  （引号句必须逐字在精读片段，否则清空为"（无合适摘录）"，宁缺毋滥）
- ④ **剧情模式双落（S127，PLAN-SKILL-UNIFY 阶段 1）**：骨架笔记一鱼两吃——
  除定位机关章（③）外，还直接派生剧情模式 plot 子条（type=plot，四要素
  granularity/position/function/params 存 ext 扩展 JSON，枚举校验回落默认
  复用 _parse_templates）——拆书一次产出整包各 type 子条（方法论 both +
  架构技法 main + 剧情模式 plot），为阶段 2（templates 并入 + 探索改读 type=plot）铺路

**关键坑（实测）**：
- 书名必须注入（book_name）——否则模型自编书名（对照组编成"赵光离的克苏鲁冒险"）
- "先原文后提问"的 prompt 措辞挡不住案例编造——必须机器校验兜底（实测仍幻觉）
- 精读片段必须含机关直接揭示段（笔记引用的章头未必覆盖，回环揭示常在章中后部）

**哲学**：机制（四层流程/选章/关键词定位/机器校验/双落）硬编码；内容（方法论/技法/剧情模式）模型生成

**S128（PLAN-SKILL-UNIFY 阶段 2）templates 物理并入**：模式库（templates_external 表 +
L2 默认模板）并入 skill 表 type=plot——L2 默认（DEFAULT_TEMPLATES）与 L3 外部数据迁移为
plot 条目，四要素+layer（default/external）存 ext 扩展 JSON；探索消费方改读
`skills.plot_skills()`（纪律 2：只读 plot 类，其他 type 不混入）；/api/templates CRUD 走
skill 表（前端 TemplateItem 形状保持，L2 默认不可删 layer=default 保护）；
ExternalLibrary 类保留在 template 包供独立测试，app 装配退役。拆书 plot 子条（S127）
确认后自动进入探索模板源——生产/消费闭环打通，skills/templates 归属竞争消除。

### 12.22 工作流扩展包（S59，主人拍板：开源路线 + 借鉴 DeterminFlow 思想）

> 背景：主人要求把"固定分析流程"（如章节质量分析）与"可迁移改书标准"（某作者
> 一套改书打法换书复用）做成 AnySpark 的**可选增强包**。DESIGN 去留清单原已将
> "工作流"列为降权可选增强包——**S114c 主人拍板：已实现部分不考虑商业化，
> 满血内置**——workflow_* 工具默认注册进 Agent 工具箱（S114b），用户直接可用。
> 本节约定其落地形态。

#### 定位
- **不是通用 DAG 业务引擎**（那是 DeterminFlow 的路），是**结构化流程三结构**：
  顺序（Sequence）+ 分支（Branch）+ 循环（Loop）——覆盖写作领域真实需求
  （"检查→返工→复检"循环、"硬伤多→重写否则→润色"分支），执行语义可证明终止。
- **与 skill 不重叠**：skill=一条知识（怎么写更好，被动注入）；workflow=多步执行
  计划（先做什么后做什么，系统主动执行、每步有输入输出、可断点恢复）。
  两者互补：流程步骤可引用 skill 作该步知识输入（骨架 do what，知识 how）。
- **与 plan/batch 的关系**：plan=章节级"接下来写什么"（推进式）；batch=流程的特例
  （单步流程）；workflow=上层编排壳（调 check/graph/plot/batch 等现有执行单元）。
- **模板与书解耦**：流程定义存模板表（与具体书无关）→ 运行任务时绑定 book_id →
  同一套"改书标准"应用到任何一本新书=迁移。

#### 引擎（机制硬编码）
- 节点类型：`agent`（调模型：写作/审读/查证指令，可带工具）/ `script`（确定性函数，
  复用 codex 沙箱）/ `approval`（人工确认点）/ `gate`（条件分支）/ `loop`（循环）。
- 边：`{source, target, condition?}`——condition 挂在边上表达分支
  （gate 出边多条件取第一个为真；loop 用 continue_condition + 最大迭代次数防死循环）。
- S129（W3-A 落地）：**loop 集合遍历原语**——params.collection_var 指向上游 JSON 数组
  （或 {batches: [...]} 对象），逐项写入 item_var（缺省 "item"）供 body 引用，迭代数=
  集合长度（max_iterations 安全上限）；与 continue_condition 条件循环二选一（校验互斥）。
  断点恢复：从 output 记录迭代数续跑，前几轮累计结果已持久化不重跑。
- 条件两种：**硬规则**（{{var}} 比较表达式，照搬 DeterminFlow condition_parser 语法：
  ==/!=/>/>=/</<= + AND/OR/NOT + 括号）与**模型判断**（自然语言条件）。
- 断点恢复：任务启动时冻结定义快照；每节点状态落盘 SQLite（pending/running/done/
  failed/skipped）；进程重启后从第一个非 done 节点续跑（借鉴 DeterminFlow CAS 防并发）。
- 失败策略：每节点 `auto_retry_count` + `auto_retry_interval_seconds` +
  `fail_auto_skip`（借鉴 DeterminFlow failure_policy，默认全关）。
- 记账：每节点 token/耗时记录（借鉴 DeterminFlow token_usage 思想）。
- 引擎算法结构借鉴 DeterminFlow（definition/condition_parser/failure_policy 的
  数据模型与状态机设计），**重写实现不搬代码**——其核心模块深度耦合它的运行时
  （NodeRegistry/SessionManager/Extension Host），直接复用会击穿 core 零依赖铁律；
  只留骨架（~2000 行 vs 其 12K 行），执行语义写作化。

#### AI 生成（对齐 skillgen 模式）
- `POST /api/workflows/generate`（描述目标 → LLM 产出流程定义候选）→ 进
  `workflow_drafts` 草稿表（未生效）→ 人工确认 promote 转正 / delete 拒绝。
- 生成时注入"节点类型目录"（各节点 schema + 用法示例 + 现有可复用能力清单），
  校验器检查节点引用完整性/类型合法/无环/条件语法，非法重试或拒收。

#### 定义格式（为画布预留）
```json
{ "id", "name", "description",
  "nodes": [{id, type: agent|script|approval|gate|loop, label, params, fail_policy}],
  "edges": [{source, target, condition?}] }
```
nodes + edges = 画布天然数据模型——现在先 JSON + API，未来前端加流程图组件
即可拖拽渲染，后端零改动（前端本期不做，主人已确认）。

#### 与 DeterminFlow 的边界（许可证已无碍）
主人确认**开源路线**（商业化与开源不冲突）→ AGPL-3.0 复用约束解除。但仍**不直接
import 复用**：耦合面问题（拖入 49K 行运行时 vs 我们只要 ~2K 行骨架）与架构铁律
（core 零依赖/单向依赖/模型无关）。只借鉴算法结构（DAG/拓扑/条件语法/失败状态机/
CAS 恢复），这些是通用计算机科学概念，重写后是自有代码。

> **S59 补充（三项）**：① script 函数白名单扩展——`read_chapter`（模糊匹配章节标题）/
> `review_chapter`（检测网审读）/ `write_chapter`（改写结果写回，库+盘双写，text_key
> 引用上游输出）/ `list_chapters` / `noop`；② workflow agent 工具（S114 后默认可用，

> 写作 Agent 可自主使用工作流（对齐 tools_domain 哲学：只读/启动，无删除权限）；

### 12.27 互动推演扩展包（S65：主人拍板独立包，与 explore 区分）

> 背景：主人提议"推演小说"功能——互动小说式推演树玩法：从某场景切入、扮演某
> 角色、每步给多个候选行动、用户选择后剧情推进、继续给选项……形成一棵推演树。
> 用途：灵感来源 + 互动玩法（有用户喜欢这种玩法）。主人拍板：**做成独立扩展包
> anyspark-play，与正文探索 explore 平级区分**（不是 explore 的子功能）。

#### 与 explore（正文探索）的本质区别

| | explore 探索 | play 互动推演 |
|---|---|---|
| 回答的问题 | 怎么写（方向/风格/结构） | 写什么（具体剧情/行动/后果） |
| 产出 | 抽象方向卡（一句话方向） | 具象剧情（场景描述+行动选项+后果） |
| 视角 | 上帝视角/写作者视角 | 第一人称扮演角色 |
| 轮次 | 单轮发散 | 多轮累积成树（选择→推进→再选择） |
| 判别 | 用户选方向（抽象） | 用户选行动（代入式） |
| 用在哪 | 开书/定调/换风格 | 写章节前/卡文时/纯玩 |

- explore 管"航向"，play 管"画面"：**探索定航向 → 推演演画面 → 写正文**
- explore.roleplay（S48-P4 单轮角色反应推演）保留不动——它是"探索"的一种手段；
  play 是新的"互动玩法"，二者定位不同

#### 机制（机制硬编码、内容自然语言）

- **回合流程**（每轮 1 次 LLM 调用，轻量上下文）：
  - 创建：seed（切入场景）+ role（扮演角色）→ 生成根节点 scene（当前局势）+ N 个候选行动
  - 选择：选 A / 自定义输入 → 结算：生成子节点 scene'（上一轮选择的后果 + 他角反应 + 新局势）
    + 新 N 个候选行动
  - 回溯分叉：从历史任意节点重走新路（树只记录，每次走一条线，不指数展开）
  - 终止：用户喊停 / 剧情自然收束（模型 options 为空）/ 最大深度（默认 20）
- **选项生成（主人修正：不硬编码策略集）**：
  - 模型自由发挥生成 3-5 个差异化候选行动（推进主线/制造冲突/出人意料/按兵不动等，
    方向由模型按场景与角色自由判断，通过提示词引导，非代码固定策略标签）
  - **自定义位是唯一硬编码**：选项列表末尾始终有"自定义行动"输入位，用户输入任意
    文本即作为所选行动进入结算（机制硬编码=这个入口；内容=用户自由输入）
- **上下文注入**（轻量）：扮演角色卡（复用 explore `load_role_card`）+ 当前节点 scene
  + 图谱角色 state（角色卡加载返回）——不背全量图谱/章节，省 token
- **跨包依赖**：play 依赖 core + explore（复用 `load_role_card` 与 `extract_json_dict`，
  避免复制=漂移源；单向链 core ← explore ← play，无环）

#### 存储（SQLite，树形）

- play_sessions：id / book_id / title / role / seed / status（running|ended）/
  max_depth / current_node_id（当前推演所在节点）/ created_at / updated_at
- play_nodes：id / session_id / parent_id（根为空）/ depth / scene / chosen_label
  （本节点由哪条选择产生，根为空）/ created_at
- play_options：id / node_id / label / is_custom（自定义位落库标记）/ chosen /
  child_node_id（选择后生成的子节点）/ created_at
- 回溯分叉：branch 把 current_node_id 指回目标节点并重新生成一批新 options 挂其下
  （原选项保留=历史记录）；choose 只允许选 current_node 下的选项

#### API + agent 工具

- `POST /api/play/sessions`（{book_id, title, role, seed, max_depth}）→ session + 根节点
- `GET /api/play/sessions`（列表）/ `GET /api/play/sessions/{id}`（树+当前路径）
- `POST /api/play/sessions/{id}/choose`（{option_id} 或 {custom_text}）→ 子节点 + 新选项
- `POST /api/play/sessions/{id}/branch`（{node_id}）→ 回溯分叉
- `POST /api/play/sessions/{id}/stop`（终止）/ `GET /api/play/sessions/{id}/export`
  （当前路径导出灵感卡 md——接 write_chapter 参考）
- agent 工具（S114 后默认可用，历史记录为 enable_play 默认关 S15 按需点亮）：play_start / play_choose /
  play_status / play_export（启动/推进/查看/导出，只读+启动，无删除，对齐哲学）
- 角色卡缺失 → 404 提示先建卡（对齐 role_play 先例）

### 12.29 路径探索（S67：叙事树节点之间串联的小方向探索）

> 背景（主人讨论）：整本书大方向已定后，"小方向的探索细腻度"——叙事树节点之间
> 怎么串联（A→B 过渡）是真实缺口。主人追问节点要不要分级：**结论不分级**（树的
> 父子关系已表达层次；kind 角色标签够用；分级=刚性约束违背"内容自由"哲学；细腻度
> 靠探索上下文粒度而非数据结构）。主人拍板由实现者自决设计并分析收益/风险。

#### 定位：三层探索粒度的中间层

```
① 大方向  explore   整本书怎么写（方向卡）       起点=种子
② 桥梁    path      叙事树节点之间怎么串（事件链） 起点=A，终点=B   ← 本次
③ 场景内  play      角色这一步做什么（行动推演）   起点=当前场景
```

- 与 play 互补：path 给骨架（中间事件链），play 演血肉（场景内行动）

#### 机制（机制硬编码、内容自然语言）

- **输入**：起点 A + 终点 B（自然语言描述，或传叙事树节点 ID 自动取内容）+ 约束
  （项目档案约束自动合并 + 请求补充）
- **输出**：N 条候选路径（单次 LLM 调用，轻量上下文），每条 = 中间事件链
  （A → 事件1 → 事件2 → B，2-5 个事件）+ note（戏剧效果/节奏）+ style（方向标签）
- **策略不硬编码**（对齐 S65 教训）：模型自由发挥不同串联思路（直推/多层铺垫/

- **落树（保守）**：默认只返回参考；`archive_index` 显式传才把选中路径的中间事件
  链式写入叙事树（candidate，第一个挂 A 下）——不自动污染树；落树需 from_node_id

#### API + agent 工具

- `POST /api/explore/path`（{from_desc|from_node_id, to_desc|to_node_id, constraints,
  book_id, n, archive_index?}）→ {paths: [{events, note, style}], archived?}
- agent 工具 `path_explore`（enable_domain 默认开：章节间过渡/情节点连接/卡文找方向）
- 错误分层：节点不存在 404 / 参数非法 400 / 模型生成失败 502（对齐 play 端点）

#### 收益 vs 风险（实现者分析）

- 收益：补上三层缺口；章节间过渡是长篇最高频卡点；机制全复用（explore 基建/JSON
  宽容解析/模型协议）成本低；与叙事树闭环对齐"探索-判别"哲学
- 风险：边界混淆（§12.29 定位锁死）；两点规划质量依赖模型（真实链路验证通过）；
  落树污染（默认不落）；并行会话冲突（提交纪律）

### 12.30 文风参考防混淆（S72：参考书 vs skill 的关系厘清 + 三件套）

> 背景（主人讨论）：资料库的文风参考（purpose=style）会被智能体当**设定**用
> （把参考书的"雾城""角色名"写进正文）。主人连问三个关键问题：
> ①"参考书和 skill 不是一回事吧"——确认：参考书=原始素材（可查原文），
>   skill=提炼后的方法论（注入写作）；正确关系=参考书→提炼→skill（S54 设计意图）
> ②"参考书有时也要读原文"——确认：skill 只摘一两段案例，模仿具体写法/氛围参照
>   必须读原文；**读原文是合法需求，不能一刀切全走提炼**
> ③结论：混淆的本质是"读了原文但没有使用边界"——修复 = 标注用途 + 边界 + 方法论通道

#### 三件套（1 治标 + 2 源头 + 3 方法论通道）

1. **read_material 标注用途 + 使用边界**（防读原文时混淆）：
   输出带 `【标题】（用途：文风参考/设定参考/两者）` + 使用边界行——
   style：仅借鉴写法（句式/节奏/用词/视角），其具体人物/地名/设定不得进入正文；
   fact：内容为权威可直接引用；both：写法可借鉴、设定可引用。工具描述同步说明。
2. **digest 按 purpose 引导**（源头防编造）：style 卡 key_points 提炼"文风特征"，
   key_settings 写适用场景或空白，prompt 明确"不得编造世界观设定"；fact/both 各
   有对应引导（_PURPOSE_GUIDES，机制硬编码、文案自然语言）。
3. **参考书 → skill 提炼链路**（方法论通道，与读原文并存非替代）：
   `/api/skills/generate` 加 `material_id`（从资料卡 source_text 取原文，与
   source_text 二选一）；agent 工具 `skill_refine`（enable_domain 默认开，生成
   候选供人工确认，不自动入库——对齐 S54 闸门哲学）。

- 渐进披露的机制成本 ≥ 省下的：LLM 判断每次 +1 调用（要喂索引才能选，1-2K token，

  后 skill_lookup 补查一次 ≈ 1-2K token，**补查 1-2 次就超过省下的**

- 目录完整可见 = 主循环能选对（质量保障）；截断目录 = 盲选风险（不知道没显示的
  技巧存在，无从点名）

**定案：技能索引保持全量常驻，不渐进披露**（YAGNI）。
**边界条件**：真到 200+ 条（上下文 16%+）再考虑——届时按类别分组折叠（目录分组、
主循环按需展开一组），不是按偏好选 2-3 条（那是盲选）。

### 12.35 审查定位：按需，不做默认环节（S74f，第一性原理定案）

> 背景（主人讨论）：真实写作复盘发现 /api/check 长文 37s~120s（审查环慢）。主人从
> 第一性原理纠偏：**审查不该是创作主链的默认环节**——用户要求时才审查。

#### 第一性原理

- **用户判别是最好的审查器**（DESIGN 机制 1：探索-判别双循环）——AI 产出后用户
  扫一眼，比任何检测网都快、都准。审查机制是**补充**，不是主审查器。
- **审查是事后按需工具，不是创作主链**：创作主链 = 规划→推演→写作（用户判别）。
  审查只在用户明确要求时（"帮我看看这章"）才跑。
- **不为默认审查优化**：既然默认不跑，check 的性能（37s~120s）在"用户主动要求"
  场景下可接受（偶发一次等一分多钟 vs 每章都等）——**不投入优化**（YAGNI）。
  真正要防的是慢请求阻塞单 worker（uvicorn 单 worker 下长 check 占死 → 其他请求
  超时），那是基础设施问题不是审查问题。

#### 现状核查（S74f 确认）

- 创作主链（chat/write_chapter）**无默认质量审查** ✓
- 审查通道全部按需：/api/check（人用）、workflow review_chapter（显式编排）、
  /api/review/panel（评审团）、batch_review（显式批量）✓
- 唯一自动的 _review_for_learning = 学习审查（章节→心智条目提炼，输入侧学习，
  **非质量把关**，合理保留）✓

#### 定位结论

- 审查 = **用户要求时**的能力（事后按需），非默认环节
- 用户判别 = 主审查器；检测网/评审 = 按需补充
- 不为审查做默认化/性能投入；基础设施（worker 阻塞）另论

### 12.37 画布布局持久化（S76 定案 → S77 实现完成）

> 背景：S76 叙事树/工作流画布完成时拖拽位置为本地状态。主人拍板方案先行、立即实现
> （S77）：方案见下，已全部落地。

#### 原则（第一性）

- **布局 = 表现层数据**，与内容解耦存储。节点/边的存在性与语义由内容表决定，
  布局只记录"用户手动调整过的坐标"；自动布局结果**不写库**（写了=噪音，且与算法
  版本耦合）。
- **批量保存、增量读取**：拖拽结束（pointerup 且 moved）时 debounce 一次批量 PUT；
  读取时随主数据一起返回（不额外往返）。
- **孤儿清理**：节点/边删除时其布局记录一并删除（内容表的删除逻辑内嵌处理，
  或布局表外键级联）。
- **版本兼容**：老数据无布局字段 → 前端自动布局兜底（现状逻辑，天然兼容）。

#### 叙事树布局

- **存储**：`story_nodes` 表加 `pos_x REAL DEFAULT NULL, pos_y REAL DEFAULT NULL`
  （NULL = 未手动调整，用自动布局）。同表同节点，无关联问题。
- **读取**：`GET /api/story/tree` 的 node.to_dict() 增加 `pos: {x,y} | null`。

### 12.36 SQLite 并发锁修复（S75：前端报告 + 全仓加固）

> 背景（前端开发者报告）：删除章节后立即对话 → 500 `database is locked`，前端
> "死机"。前端分支 docs/BACKEND-ISSUES.md 有完整错误分析（根因推断），后端核对
> 后确认：**分析正确，后端此前未修复**。

#### 根因（核实前端分析）

1. **ChapterStore.delete() 缺 commit**（sqlite.py）：`with self._lock:` 内执行 DELETE
   无 commit → 事务保持打开、锁持续持有 → 后续任何写请求（chat 的 decay_stale
   UPDATE 等）500 locked。**这是锁的直接根因**。
2. **无 WAL + 默认 timeout=5**：15+ store 各自独立 connect 同一 db，rollback journal
   模式读写互斥，高并发脆弱（放大问题）。

#### 修复（最小修复 + 全仓加固）

1. **ChapterStore.delete 补 commit**（核心）
2. **全部 store connect 加 `timeout=30` + `PRAGMA journal_mode=WAL`**（18 个 store 文件
   统一：align 9 + app 2 + explore 1 + graph 1 + play 1 + template 3 + workflow 1；
   WAL 允许读并发 + busy_timeout 30s 宽容写竞争）——防任何 store 再缺 commit 时
   锁死整个系统

#### 验证

- 真实链路（新进程）：删章→立即对话 ✓ / 连续删 3 章→对话 ✓（旧进程复现 500，
  换新代码后消失）
- 测试：ChapterStore.delete 后立即写 ✓；WAL 模式存在 ✓
- AST 全仓扫描确认无其他缺 commit 的写方法（graph/storytree/registry 均正常，
  SqliteConversationStore 用 with self._conn 上下文事务）

### 12.39 双层资料库（S79：全局大池子 ↔ 项目小池子，kind 冷藏机制）

> 背景：前端出现"全局资料库"与"书内资料库"两个入口，实为同一组件+同一 API
> （S74 的 book_id 隔离未接 API，全落 main）。主人厘清概念后拍板：
> **全局池保留（大池子）+ 项目池（小池子），半独立可互相导入**。

#### 资料库定位（主人定案）

- 资料库 = **灵感/参考冷藏库**，不是写作主循环的知识源（**不注入**，需要时检索/导入）
- 内容分两类，可见性不同：
  - **inspiration（灵感卡）**：随想灵感/历史文献/参考笔记——智能体**可见可检索**（read_material 命中）
  - **copy（重叠副本）**：从全局池/设定/图谱复制的重叠内容——智能体**不可见、检索不命中**，仅前端人工查看（纯冷藏备份）
- **导入语义 = 复制 + 溯源 + 标 copy**：导入的卡带 source_ref（global:<卡id>），
  不自动成为智能体可见内容；用户手动「转灵感」才可见

#### 数据模型（materials 表）

- `book_id`：`"global"`（全局大池子）/ `<书id>`（项目小池子）——S74 字段正式接线 API
- `kind TEXT DEFAULT 'inspiration'`：inspiration / copy
- `source_ref TEXT DEFAULT ''`：copy 卡溯源
- 智能体工具一律 `kind='inspiration'` 过滤：read_material（tools_extras）、skill_refine（tools_domain）

#### API

- `GET /api/materials?book_id=&kind=`（kind=all 显示全部）；`POST /api/materials` 带 book_id/kind
- `POST /api/materials/import {card_id, from_book_id, to_book_id}` → 复制+溯源+标 copy
- `POST /api/materials/{id}/promote` → copy 转 inspiration（人工闸门）
- `GET /api/workspace?book_id=`（上传区总览按书，S48 补接线）；`GET /api/upload/{book_id}/{filename}`（素材文件访问/图片展示）

#### 前端

- 书架页「资料库」tab = **全局池**（book_id=global）；书内「资料」tab = **项目池** + 「从全局池导入」
- copy 卡「冷藏」角标 + 「转灵感」按钮
- UploadPanel 支持图片（accept 放开 + 缩略图 + 素材标记）——图片无文本消化路径，纯素材存放（未来多模态接入）

#### 与 S86 参考书库（anyspark-library 包）的关系

- 参考书库 = **整本参考书文件**（全局 data/library/ + 项目选书，只读检索不注入）
- 资料库 = **摘要卡/灵感卡**（双层池，kind 控制可见性）
- 两者互补不重叠：参考书是"书"，资料库是"卡"；skill_refine 拆书（S78）从任一来源取原文提炼方法论

### 12.44 多模型兼容协议（S131：openai/anthropic/gemini/responses，主人拍板"达到 Pi 水平"）

**背景（主人指示）**：模型提供商支持向 Pi 看齐——至少覆盖所有主流模型厂商 + 本地。
现状盘点：主流厂商 90% 是 OpenAI Chat Completions 兼容（DeepSeek/通义/Kimi/GLM/豆包/
Groq/Cerebras/Mistral/xAI/OpenRouter/本地 Ollama/LM Studio/vLLM/llama.cpp），一个
openai 协议适配器全覆盖；真正缺的是三个独立协议——Anthropic Messages（Claude
直连/中转）、Google Generative AI（Gemini 直连）、OpenAI Responses（GPT-5 系，
chat.completions 用不了 gpt-5）。

**协议注册表**（ModelConfig 加 `protocol` 字段，SQLite 列默认 'openai'，旧库启动
ALTER 自动迁移）：
| protocol | 适配器 | 覆盖 | 思考强度映射 |
|---|---|---|---|
| openai | DeepSeekModel（泛化） | 绝大多数厂商 + 本地 | reasoning_effort / enable_thinking（原有） |
| anthropic | AnthropicModel | Claude 直连/中转 | thinking: {budget_tokens}（low=2048→max=32768；开启时温度强制 1） |
| gemini | GeminiModel | Gemini 直连 | thinkingConfig: {thinkingBudget}（off=0） |
| responses | ResponsesModel | GPT-5 系 | reasoning: {effort}（xhigh/max 封顶 high） |

**设计要点**：
- core Model 协议零改动——新适配器实现同一协议（respond/respond_stream/model_name/
  context_window），Agent/图谱/检测/探索/后台全组件自动跟随，无感知
- ModelProvider.build 按 cfg.protocol 分发到协议工厂（openai 保留注入工厂供测试），
  缓存 key 含 protocol（同 id 改协议立即重建）
- 工具调用三协议原生支持：anthropic tool_use 块 + tool_result 回填（相邻同角色消息
  合并满足严格交替）；gemini functionCall + functionResponse；responses 扁平
  function tool + function_call_output item
- 思考强度档位四协议统一（off/low/medium/high/xhigh/max），各协议按能力映射；
  Anthropic 的 thinking enabled 强制 temperature=1（API 硬性限制）
- **零新增依赖**：anthropic/gemini 用 httpx2 手写 HTTP（Messages/Generative AI 是
  简单 JSON API）；responses 复用 openai SDK（client.responses，2.x 原生）
- **代理坑（实测发现）**：openai SDK 默认 client 读环境变量代理（trust_env=True），
  把本地端点（127.0.0.1 Ollama/vLLM）请求发到代理导致 502——deepseek/responses 适配器
  显式传 httpx2 Client(trust_env=False)；anthropic/gemini 手写层本就走 trust_env=False
- **哲学保持**：协议选择/端点/模型名是自然语言数据可增删改；机制（分发/转换/映射）
  硬编码；模型无关（换协议不换组件逻辑）继续成立
- **YAGNI 边界**：Bedrock/Vertex 原生 SDK（重依赖 boto3/google-auth + 云账号，
  国内基本用不到）不预建；本地模型全部走 openai 协议（base_url 指本地端点）
